# LLMOps 자료 편집 기록

검토일: 2026-09-28. 로컬 `llmops/`의 HTML 5개를 본문, JavaScript에 저장된 설명 데이터, 포함된 화이트보드 이미지까지 확인했다. 원본 HTML·사진·논문 그림은 배포하지 않는다. 기술적인 주장은 글 본문의 원 논문과 공식 문서 링크에서 확인할 수 있게 했다.

## 주제 통합

| 입력 자료 유형 | 게시한 내용 |
| --- | --- |
| 전체 지도·입문 용어 설명 | 운영 / 프롬프트·RAG·에이전트 / 후학습 / 서빙으로 재분류 |
| 모델 생애·화이트보드 설명 | 학습 목표, rollout·verifier, 계보와 실행 권한 |
| 내부 운영 미션 | 평가, 릴리스 단위, Shadow·카나리·A/B, 피드백 절차 |
| PagedAttention 장별 해설 | 메모리 문제·메커니즘·성능 해석 중심의 독립 연구 노트 |
| 기존 블로그의 관측 구현 | OpenTelemetry 글로 연결하고 구현 설명의 중복 생략 |

## 검토에서 수정한 내용

- 필수 4단계 생애로 단정하지 않고 기존 모델 사용·평가용 rollout 등 경로를 구분했다.
- 샘플링의 다양성 조절을 안전성·사실성·완전한 재현성과 구분했다.
- 지식/RAG·행동/튜닝은 선택 휴리스틱으로 표현했다.
- Self-RAG의 reflection token 학습을 일반 자기 비평 프롬프트와 구분했다.
- RAG·벡터 DB, ANN recall·업무 검색 recall을 구분했다.
- 임베딩 모델 변경 시 차원만으로 호환성을 판단하지 않도록 수정했다.
- SFT·DPO와 LoRA를 서로 다른 축으로 설명했다. RLHF를 PPO로 한정하지 않았다.
- QLoRA의 저장 정밀도와 연산을 구분하고 paged optimizer와 PagedAttention을 구분했다.
- GGUF를 GPTQ·AWQ와 동급의 양자화 알고리즘으로 분류하지 않았다.
- GQA KV head 수, KiB·GiB 단위, 메모리 계산의 가정과 예외를 명시했다.
- Prefix caching은 주로 prefill을 줄이며 response caching과 다름을 명시했다.
- Shadow는 사용자에게 후보 응답을 노출하지 않는 방식이지 무부작용 보장이 아님을 명시했다.
- MCP·샌드박스·가드레일을 권한 통제의 대체물로 설명하지 않았다.
- 모델 제공자의 데이터 이용을 일괄 단정한 문장은 삭제했다.
- PagedAttention의 2–4배·96.3%·20–26%를 측정 대상·실험 조건과 함께 썼다.
- 2023년 논문의 메커니즘과 현재 vLLM V1의 복구 방식 설명을 구분했다.

## 편집 원칙

반복 비유, 장별 요약의 재요약, 근거 없는 도구 순위와 성능 보장, 내부 인물·고객·팀 성과 소개는 싣지 않았다. 특정 공급자 소개 대신 공통 운영 판단을 남겼다. 새로운 글은 연구·설계 노트로 표시하고 실제 구축 성과를 창작하지 않았다. 설명용 숫자·설정과 논문 실험 결과를 구분했다.

글은 기존 Markdown collection을 사용하므로 홈 목록·검색·목차·RSS에 포함된다. 검색 제외 메타 태그와 robots 설정은 유지한다. 로컬 원본은 `.gitignore`에 추가해 공개 저장소에 실수로 포함되지 않도록 했다.
