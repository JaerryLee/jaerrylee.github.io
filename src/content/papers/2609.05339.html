01Problem · 같은 저장소, 다른 해석기

모델만 바꿨는데 기억이 사라질 수 있다

한눈에 요약

agent memory는 단순 파일이 아니라 writer·embedding·retriever·reader가 함께 만든 실행 결과다.

저장 파일을 그대로 복사하는 것과 새 모델이 같은 사실을 다시 꺼내는 것은 별개다.

이 논문은 memory migration을 ‘파일을 옮겼나?’가 아니라 새 모델이 이전 사실을 정확히 재사용하나?로 정의한다.

자연어 NOTES는 옛 모델이 무엇을 중요하다고 판단해 어떤 표현으로 압축했는지에 묶인다. RAG index는 문서와 query가 같은 embedding 공간에서 비교된다는 계약에 묶인다. fixed-schema KG는 표현을 정해진 slot으로 정규화하므로 writer 차이를 줄이지만, schema가 담지 못한 사실은 애초에 저장하지 못한다.

초등학생도 이해하는 설명

옛날 선생님이 만든 요약 노트를 새 선생님이 읽으면 뜻을 다르게 볼 수 있다. 도서관 책 위치표를 새 좌표계와 섞으면 책을 못 찾는다. 반대로 이름·전화번호 칸이 정해진 주소록은 누가 써도 읽기 쉽지만, 좋아하는 음식 칸이 없으면 그 정보는 사라진다.

02Memory Forms · 무엇을 영구 저장하는가

원문, vector index, 자연어 note, fixed KG는 실패 위치가 다르다

한눈에 요약

LC-RAW는 전체 history를 넣고, RAG는 512자 chunk를 top-8 검색한다.

NOTES는 모델이 요약한 내용을, KG-fixed는 subject–predicate–object fact를 고정 schema로 보존한다.

LC-RAW는 write 단계 손실이 거의 없지만 history가 길어질수록 입력 비용이 커진다. RAG는 원문 chunk를 보존해도 retrieval이 실패하면 reader에게 사실이 도달하지 않는다. NOTES는 짧지만 작성 시 누락·왜곡되면 저장소만으로 복구할 수 없다. KG-fixed는 이 실험에서 가장 안정적이지만, workload에 맞춘 schema와 별도 graph query read path를 썼다.

한눈에 요약

06Design & Limits · migration contract

memory에는 writer·embedding·schema 버전을 함께 저장해야 한다

한눈에 요약

raw source retention, embedding space isolation, 양방향 migration test가 핵심 운영 원칙이다.

두 소형 모델·synthetic history·단순 RAG·workload 맞춤 schema만 평가했으므로 보편적 우열표는 아니다.

이 논문의 가치가 큰 곳은 ‘어떤 memory가 최고인가’보다 어떤 dependency를 버전 관리해야 하는가를 보여 준 데 있다.

store metadata에는 writer model, embedding version, schema/prompt version을 기록해야 한다. re-embedding이나 note rewrite를 할 수 있도록 원문 provenance도 보존해야 한다. 개인정보·보존 비용 때문에 raw history를 무기한 저장할 수 없다면, 복구 가능성과 삭제 정책의 trade-off를 명시해야 한다.

주의할 점도 크다. Llama/Qwen 두 모델은 크기와 계열이 비슷하고 history는 합성이다. RAG는 512-character chunk, cosine top-8뿐이며 reranker·hybrid retrieval·query rewriting이 없다. KG는 과제에 맞춘 fixed schema와 다른 read mode를 쓰므로 ‘KG가 언제나 최고’의 증거가 아니다. 코드와 결과도 공개 저장소가 아니라 요청 시 제공이라고 적혀 있다.

초등학생도 이해하는 설명

이사 상자 겉에 ‘누가 썼는지, 어떤 자로 길이를 쟀는지, 어떤 칸 규칙인지’를 적어야 한다. 원본을 버리면 잘못 옮긴 뒤 다시 만들 수 없다. 다만 이 실험은 작은 모형 집 두 채의 이사라서 모든 도시 이사에 그대로 적용할 수는 없다.

＋Retrieval Family · 검색 계열 1차 판별

RAG와 fixed KG memory를 비교하지만 GraphRAG 논문은 아니다

한눈에 요약

KG-fixed는 subject–predicate–object 저장소지만 community report·DRIFT·PPR는 없다.

RAG 쪽은 일반 dense vector retrieval이며 graph는 비교 대상 memory 형식이다.

community report · global/local search · DRIFT가 없으므로 Microsoft GraphRAG가 아니다. Personalized PageRank · passage node · associative memory도 없으므로 HippoRAG가 아니다. subgraph · path retrieval을 이용해 답을 찾는 새로운 graph-based RAG도 아니다. HNSW 같은 ANN graph를 분석하지도 않는다. 이 연구의 초점은 서로 다른 memory representation이 모델·embedding 교체를 견디는지다.

초등학생도 이해하는 설명

이 논문에는 그래프 상자가 나오지만, 그래프 길을 따라 검색하는 새 방법을 만든 것은 아니다. 일기장·검색 카드·요약 노트·관계 주소록 중 어느 상자가 이사에 강한지 비교한 실험이다.

핵심 용어 정리

Writer coupling작성 모델 결합

memory 표현이 그것을 쓴 모델의 선택·표현 습관에 의존하는 정도다.

Embedding space벡터 좌표계

문장 의미를 숫자 위치로 배치하는 규칙이다. 차원이 같아도 버전이 다르면 좌표 의미가 다를 수 있다.

Re-embedding전체 재벡터화

보존된 원문 chunk를 새 embedding 모델로 모두 다시 변환하는 일이다.

Fixed schema KG고정 틀 지식 그래프

허용된 관계와 필드를 미리 정하고 사실을 triple로 저장한 memory다.

Exact match완전 일치

출력 문자열이 정답 코드와 정확히 같은지 보는 엄격한 평가다.
