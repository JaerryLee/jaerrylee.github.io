01Motivation · 동기

셸의 강력함과 위험

한눈에 요약

셸은 파일·프로세스·네트워크를 직접 조작해 자동화하기 좋지만 한 글자 오타가 데이터를 덮어쓸 수 있다. ShellVis는 라이브 실행과 파일시스템 샌드박스를 결합한다.

기존 편집기를 그대로 쓰고 결과는 별도 시각화기에 표시한다. 파일 효과는 overlay 계층에서 시뮬레이션한다.

초등학생도 이해하는 설명

실제 방이 아닌 가상 방에서 로봇이 정리하게 해 보는 것과 같다. 네트워크 효과는 완벽히 흉내 내지 못한다.

02Trace & View · 추적

편집→실행→추적→보기

한눈에 요약

stdout, 변수, 작업 디렉터리, 파일 추가·삭제·수정을 명령별 bubble로 보여 준다. 루프는 슬라이더로 반복을 선택하고 현재 커서 주변만 자세히 확장한다.

사용자는 echo를 직접 넣지 않고 EXIF, 파이프, 변수 값을 단계별로 본다.

초등학생도 이해하는 설명

책 문장 옆에 실행 결과 메모가 자동으로 붙는 것과 같다.

03Design · 설계

기존 셸 습관을 유지한 인터페이스

한눈에 요약

inline bubble은 정보가 많을 때 원문을 밀어내므로 오른쪽 패널·축약 bubble·루프 슬라이더를 채택했다. 파일 효과는 매 실행 초기화된다.

WebSocket으로 편집기 커서와 시각화기의 초점을 연결한다. 네트워크·프로세스 효과는 향후 과제다.

초등학생도 이해하는 설명

연습 모드에서만 저장 파일을 바꾸는 것과 같다.

04User Study · 평가

7명의 참가자

한눈에 요약

셸 경험 1~20년의 7명이 네 가지 작업을 수행했다. 도움됨·샌드박스 평균은 5.0/5, 자기 작업 유용성은 4.9/5였지만 작은 질적 연구다.

참가자는 echo 로그 수고가 줄고 원인 분석이 쉬워졌다고 말했다. 두 창의 화면 점유와 반복 전체 가시성은 한계였다.

초등학생도 이해하는 설명

7명이 좋다고 답한 것은 신호이지 모든 개발자에게 일반화되는 증거는 아니다.

05Limits · 한계

안전한 라이브 프로그래밍의 다음 단계

한눈에 요약

파일시스템 외 효과의 격리, 편집기 통합, 반복 전체의 가시성, 파이프 행 추적, 도메인별 시각화가 남은 과제다. LLM 코드 보조와 결합은 직접 평가되지 않았다.

ShellVis는 무엇을 쓸지보다 이미 쓴 코드가 무엇을 했는지 이해시키는 도구다.

초등학생도 이해하는 설명

안전벨트가 목적지까지 운전해 주지는 않는다. 이 도구도 명령을 대신 정하지 않는다.
