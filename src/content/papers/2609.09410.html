01MOTIVATION · 배경

웹만도, 데이터베이스만도 아닌 질문

한눈에 요약

실제 조사 질문은 공개 웹의 설명과 DB의 정확한 수치를 동시에 요구한다. 이 논문은 9개 LiveSQLBench DB와 Wikipedia/FineWeb 코퍼스로 380개 tool-dependent task를 만들었다.

GraphRAG가 아니라 web search + SQL을 결합한 agentic retrieval benchmark다. 그래프는 증거 설계에 쓰였지만, 평가 대상은 출처 간 조정이다.

초등학생도 이해하는 설명

어떤 문제는 인터넷에서 이름을 찾아야 하고, 동시에 계산기 장부에서 숫자를 꺼내야 한다. 두 곳을 모두 봐야 답할 수 있다.

검색 계열 1차 판별

RAG·검색 연구이지만 GraphRAG는 아니다. 벡터 그래프가 아니라 웹 검색 결과와 SQL 실행 결과를 결합하는 에이전트 평가다.

02TASKS · 과제 구조

에이전트가 오가는 길을 세 가지로 나눴다

한눈에 요약

SQL2S는 SQL로 고유명사·제약을 얻고 웹을 찾는다. S2SQL은 웹에서 단서를 얻어 SQL 조건을 만든다. Parallel은 두 결과의 교집합을 구한다.

실패는 검색 정확도만이 아니라 “앞 단계의 조건을 다음 도구가 잊는가”에서 생긴다.

초등학생도 이해하는 설명

먼저 장부에서 “누구인지” 찾고 인터넷에서 설명을 찾거나, 인터넷에서 사람을 찾은 뒤 장부에서 숫자를 계산한다. 순서를 잊으면 틀린다.

03RESULTS · 결과

최신 모델도 방향성 handoff에서 크게 무너진다

한눈에 요약

균형 난제 120개에서 GPT-5 Pass@8은 54.17%, Claude-Sonnet-4.6은 52.50%, GLM-5.2는 50.83%였다. Parallel은 약 77.5%였지만 S2SQL·SQL2S는 30–47.5% 수준이었다.

전체 380개에서 Qwen3.5-397B + MiroFlow는 Corpus Search Pass@8 63.42%, smolagents 56.58%였다.

04FAILURES · 실패와 한계

검색 실패보다 “조건을 잊는 것”이 더 치명적이다

한눈에 요약

대표 실패는 SQL 결과를 웹 검색에서 잃어버림, 웹에서 찾은 후보를 SQL에서 잘못 집계, 병렬 결과를 교집합하지 않고 한 출처 후보를 답으로 채택하는 것이다.

MiroFlow는 Pass@8을 높였지만 더 많은 호출과 timeout(완료율 smolagents 83.3%, MiroFlow 58.8%)을 지불했다.

초등학생도 이해하는 설명

두 친구가 각각 인터넷과 장부에서 답을 찾았는데, 마지막에 둘의 조건을 합치지 않으면 엉뚱한 사람을 고르게 된다.

＋One-page Summary · 한 장 정리

이 논문을 한 장으로

01
하이브리드 검색의 병목은 출처 간 handoff와 제약 보존이다.
02
균형 120개에서 최신 모델 Pass@8도 50–54% 수준이다.
03
Parallel이 방향성 SQL2S/S2SQL보다 훨씬 쉽다.
04
MiroFlow는 한 번 성공할 확률을 올리지만 호출·timeout 비용이 크다.
05
정말 쉽게 한 문장: 인터넷과 장부를 둘 다 봐야 하는 문제에서는, 앞에서 찾은 힌트를 끝까지 잊지 않는 것이 핵심이다.
