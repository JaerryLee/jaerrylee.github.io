01Problem · 입력

자연어 문장을 바로 코드로 쓰면 조건을 빠뜨린다

한눈에 요약

정책은 Decision, Subject, Action, Resource, Condition, Purpose로 분해해 구조화합니다.

baseline은 고정 prompt 한 번으로 Rego를 만들고, 제안 시스템은 같은 Claude(temperature 0)로 구조화·검증 단계를 추가합니다.

보안 정책에서 “컴파일된다”는 “권한 의미가 맞다”와 다릅니다. 특히 deny, 소유자, 상태 조건 누락은 실행 오류 없이 과도한 허용으로 이어질 수 있습니다.

ACRE 485문장 중 subject·action·resource가 모두 있는 372개를 평가했습니다. 스키마는 조직이 허용하는 속성 vocabulary를 제한해 모델이 존재하지 않는 필드를 만들지 않도록 합니다. 입력이 명확하지 않은 166개를 거부하는 것도 안전한 동작으로 봅니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: “누가 어떤 문을 열 수 있나”를 바로 컴퓨터 명령으로 옮기지 않고, 사람·행동·문·조건을 체크리스트로 나누는 것입니다. 작은 예: 관리자는 계정을 수정할 수 있지만 삭제는 보안팀 승인 필요라고 분리합니다. 논문 대응: DSARCP 필드가 자연어 요구를 검증 가능한 중간 표현으로 만듭니다.

02Architecture · 파이프라인

생성기보다 앞뒤의 결정론적 문턱을 늘린다

한눈에 요약

pre-processing이 정책 후보를 정리하고, generator가 DSARCP를 채우며, schema validator가 필수 필드와 vocabulary를 검사합니다.

Rego 생성 뒤 OPA compile·Regal lint·테스트 생성·실행을 통과해야 최종 정책으로 인정합니다.

모델의 한 번의 답을 믿는 대신, 입력·중간 구조·출력·실행 결과에 각각 실패 지점을 둡니다.

파이프라인은 LLM provider를 바꿔도 같은 모듈 경계를 유지합니다. prompt는 중앙 관리하지만, redundant-block consolidation과 semantic safety guardrail, condition-aware test repair는 LLM 밖에서 결정론적으로 동작합니다. LLM 기반/규칙 기반 테스트 생성을 선택할 수 있습니다.

03Verification · 테스트

positive와 negative를 모두 통과해야 배포 가능한 정책으로 센다

한눈에 요약

positive test는 모든 조건을 만족하는 허용 예, negative test는 하나 이상의 조건을 깨는 거부 예입니다.

생성된 테스트가 조건 일부를 빠뜨리면 Rego 본문에서 equality·membership 조건을 추출해 입력을 보완하고, negative가 우연히 허용되면 조건 하나를 결정론적으로 깨뜨립니다.

여기서 “정답”은 자연어 의미의 완전한 증명이 아니라, 컴파일·lint·두 테스트를 모두 통과한 operational validity입니다.

복합 조건·외부 상수·시간 변수·타입 변환은 테스트 생성의 취약점으로 남습니다. 기본 deny 정책의 명시적 deny가 빠지는 문제는 compile/lint만으로 검출되지 않아 런타임 테스트가 필요합니다.

04Evaluation · 결과

구조적 파이프라인이 coverage와 보안 조건을 함께 높였다

한눈에 요약

372개 전체에서 effective correct coverage는 direct 15.3%(57/372) 대 pipeline 50.3%(187/372)였습니다.

77개 양쪽 모두 출력한 겹침 집합에서는 네 기준 모두 통과가 74.0% 대 90.9%였고, deny completeness 37.5% 대 87.5%, ownership 40% 대 100%, status 55.6% 대 100%였습니다.

baseline은 쉬운 정책만 출력해 compile 비율이 높아 보일 수 있으므로, 전체 집합과 겹침 집합을 분리해 봐야 합니다.

Direct LLM은 372개 중 77개만 시도했고, pipeline은 206개를 valid NLACP로 받아들였습니다. 따라서 pipeline의 compile 54.0%는 더 어려운 입력까지 시도한 결과입니다. role-check 수치가 pipeline에서 낮아 보이는 것은 set-membership 표현을 단순 regex가 놓친 측정 artefact이며, 저자들은 해당 정책이 테스트를 통과했다고 설명합니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 쉬운 문제만 푼 학생과 어려운 문제까지 푼 학생을 같은 합격률로 비교하지 않는 것입니다. 작은 예: 둘 다 답을 낸 77문제에서는 구조화 시스템의 테스트 통과율을 따로 비교합니다. 논문 대응: 전체 coverage와 overlap quality를 분리한 평가 설계입니다.

05Limitations · 보안

테스트 기준의 correctness는 의미적 동등성의 증명이 아니다

한눈에 요약

ACRE의 정답 주석과 compile/lint/tests로 측정했으므로, 실제 조직 정책 의도와의 완전한 의미 동등성은 확정하지 않습니다.

Claude 한 모델, 372개 필터링된 문장, provider 비용·지연·사람 검토가 보고되지 않아 운영 효과를 일반화할 수 없습니다.

실무 도입에서는 모델 출력보다 정책 vocabulary, deny 기본값, 테스트 생성기의 독립성, 사람 승인 경계를 먼저 설계해야 합니다.

저자들은 외부 상수·복합 조건·시간 조건에서 테스트 생성이 약하다고 밝힙니다. 보안 팀은 각 정책에 원문 요구, DSARCP, 생성 Rego, positive/negative fixture, OPA 실행 로그를 함께 보관하고, 생성기가 만든 fixture를 별도 검토해야 합니다. 입력을 거부하는 보수성은 coverage를 낮추지만 과도한 권한 허용보다 안전한 trade-off입니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 자동차가 시동되고 시험 코스를 통과해도 실제 도로의 모든 위험을 증명한 것은 아닙니다. 작은 예: 테스트에 없는 시간 조건이 운영에서 바뀌면 정책이 틀릴 수 있습니다. 논문 대응: compile/lint/test correctness와 자연어 의도 동등성을 분리해 읽어야 합니다.
