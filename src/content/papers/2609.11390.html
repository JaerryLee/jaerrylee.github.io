01Background · 배경

책·규정·논문은 납작한 문장 목록이 아니다

한눈에 요약

구조화 문서는 장–절–항–부록의 계층을 가진다. 단순 chunk 임베딩은 이 구조를 끊어 여러 곳에 흩어진 근거를 놓칠 수 있다.

정말 쉽게 한 문장

책의 목차를 통째로 프롬프트에 넣지 않고, 필요한 목차 조각만 찾아가며 답을 만드는 RAG다.

초등학생도 이해하는 설명

백과사전에서 답을 찾을 때 책 전체를 들고 오지 않고, 목차에서 3쪽·7쪽만 확인한 뒤 모자란 부분이 있으면 더 찾는 것이다.

VikingRAG의 차별점은 지식 그래프를 새로 만드는 것이 아니라, 원래 문서의 디렉터리 계층을 검색 가능한 상태로 보존하는 데 있다.

기존 DeepRead는 후보 문서의 전체 디렉터리를 LLM에 계속 보여줘 토큰이 커졌다. VikingRAG는 필요한 directory segment만 on-demand로 노출한다.

02Method · 방법

한 번 찾고 끝내지 말고, 남은 빈칸을 보고 다시 찾는다

한눈에 요약

에이전트는 첫 검색 결과를 읽고 어떤 사실이 부족한지 판단한다. 그 빈칸을 채우는 새 query로 다음 directory segment를 검색하는 multi-round loop를 수행한다.

초등학생도 이해하는 설명

선생님이 “이름은 찾았는데 생일이 없다”고 말하면, 생일이 있을 법한 다른 페이지를 다시 펼쳐 보는 방식이다.

VikingRAG-E는 과거의 검색 trace를 query-conditioned experience edge로 저장하고, 비슷한 질문에서 그 경로를 재사용한다.

VikingRAG-E+는 한 번 검색한 증거가 충분한지 checker가 판단한 뒤 어려운 질문에만 agentic escalation을 켠다. 쉬운 질문에 매번 긴 대화를 시키지 않는 구조다.

03Results · 결과

정확도를 크게 잃지 않고 토큰을 줄였다

한눈에 요약

저자들은 여러 구조 문서 데이터셋에서 VikingRAG가 SOTA 대비 11.6–51.9% 토큰을 사용한다고 보고한다. trace 재사용과 선택적 escalation을 더하면 5.1–32.5%까지 내려간다.

초등학생도 이해하는 설명

문제를 잘 풀던 친구의 풀이 순서를 메모해 두었다가, 비슷한 문제에서는 처음부터 다시 헤매지 않는 것이다.

경험 edge는 답을 저장하는 것이 아니라, “이 질문은 이 문서 조각을 이렇게 찾아가면 된다”는 경로를 저장한다.

문서 수를 너무 줄이면 근거가 부족해 재검색이 늘고, 너무 늘리면 관련 없는 토큰과 지연이 커진다. 저자들의 기본값 K=10, L=1000, B=15는 이 절충 위에 있다.

04Trade-offs · 비용

빠른 길을 미리 저장하려면 문서가 어느 정도 안정적이어야 한다

한눈에 요약

experience edge 생성에는 몇 초의 오프라인 비용과 저장공간이 든다. 문서·질의 분포가 계속 바뀌면 오래된 경로가 덜 유용해질 수 있다.

초등학생도 이해하는 설명

자주 가는 문구점까지 지름길을 지도에 표시하면 편하지만, 길이 공사로 바뀌면 지도를 다시 그려야 한다.

adaptive escalation은 오답 위험을 줄이지만, checker가 “충분하다”고 잘못 판단하면 필요한 재검색을 건너뛸 수 있다.

논문은 false-NoEscalation 비율이 여러 데이터셋에서 5%를 넘는다고 보고한다. 따라서 비용 절감률을 정확도와 함께 보고, 경험 edge의 신선도·삭제 정책·도메인 이동을 운영 지표로 삼아야 한다.

05Limits · 한계

이 그래프는 지식 그래프보다 ‘문서 목차 그래프’에 가깝다

한눈에 요약

VikingRAG의 그래프성은 entity–relation 지식 그래프보다 parent–child directory tree와 검색 trace edge에 있다. 따라서 GraphRAG의 개체 경로 추론과 같은 문제를 푸는 시스템으로 오해하면 안 된다.

초등학생도 이해하는 설명

사람과 사물의 관계를 그린 친구 관계도가 아니라, 책의 목차와 “이 페이지에서 저 페이지로 갔다”는 이동 기록을 그린 지도다.

비교 기준선에 HippoRAG-2·LightRAG·BookRAG가 포함되지만, 핵심 기여는 계층 구조를 LLM 컨텍스트에서 분리하고 evidence gap을 따라 다시 찾는 것이다.

실제 배포에서는 문서 파싱 품질, 디렉터리 요약 오류, 경험 edge의 개인정보·문서 변경 전파를 검증해야 한다.

검색 경험칙

directory tree·evidence gap·experience edge가 보이면 구조 문서용 agentic RAG다. entity·relation·community/path가 중심이면 넓은 의미의 GraphRAG이고, HNSW/Vamana면 벡터 검색 내부 도로다.
