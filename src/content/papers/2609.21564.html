01Architecture · 구성

데이터와 변환을 하나의 버전 관리 가능한 그래프로 만든다

한눈에 요약

RDF 소스·named graph·SPARQL 변환·검증 쿼리를 YAML 설정에서 선언합니다.

GraphDB, Fuseki, RDF4J, QLever를 지원하지만 상태는 별도 서비스가 아니라 triplestore 안에 둡니다.

kgsteward는 ETL 도구와 비슷하지만 중간 단계마다 named graph가 남고, 그 그래프를 SPARQL로 바로 검사할 수 있다는 점이 핵심입니다.

소스는 로컬 파일, URL, 부모 dataset의 named graph가 될 수 있습니다. pre-import shell은 압축 해제 같은 준비를 하고, post-import SPARQL UPDATE는 오류 수정·링크 보강을 수행합니다. 환경변수와 glob, !include로 비밀·반복 설정을 분리하며, 설정 파일 자체가 협업의 계약이 됩니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 레시피 카드 하나에 재료, 손질, 조리, 맛보기 기준을 모두 적어 두는 주방입니다. 작은 예: CSV를 읽고 이름을 정규화한 뒤 품질 쿼리가 0행인지 확인합니다. 논문 대응: YAML과 SPARQL 파일이 소스·변환·테스트를 함께 버전 관리합니다.

02Incremental Build · 변경 감지

SHA-256과 부모 순서로 필요한 dataset만 다시 만든다

한눈에 요약

dataset의 입력·스크립트·부모·stamp를 해시해 변경을 감지합니다.

부모가 재구축되면 자식도 재구축하며, 선언 순서대로 한 번만 전진하므로 부모가 먼저 완성됩니다.

원격 URL의 Last-Modified/Content-Length도 checksum에 넣어 불필요한 대용량 다운로드를 피합니다.

named graph가 없거나, 선언된 입력이 바뀌거나, 부모가 갱신되거나, 사용자가 force rebuild하면 재수입합니다. 로컬 파일은 내용 전체를 해시하지만, 원격 파일은 서버 헤더에 의존합니다. 주석 한 줄만 바꿔도 shell script checksum이 바뀌는 것은 보수적이지만 rebuild가 늘어나는 trade-off입니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 창고 선반마다 내용물의 지문을 붙여 바뀐 상자만 다시 포장하는 방식입니다. 작은 예: dataset B의 파일만 바뀌면 B와 B에 의존하는 C를, A는 건드리지 않습니다. 논문 대응: kgsteward는 입력 checksum과 부모 상태로 선택적 rebuild를 결정합니다.

03Validation · 실제 적용

검증 쿼리가 테스트이면서 사용 설명서가 된다

한눈에 요약

SPARQL query collection은 결함이면 행이 나와야 하는 진단 쿼리와, 예시를 보여 주는 문서 쿼리를 함께 담습니다.

Sinergia Wolfender 그래프는 644,544,052 triples 규모로 구축됐고, 수십 개 검증 쿼리가 매 build 뒤 실행됩니다.

테스트가 데이터와 분리된 문서가 아니라, 실제 endpoint에서 실행할 수 있는 예시라는 점이 운영·AI 접근성을 동시에 높입니다.

SHACL 대신 SPARQL을 택한 이유는 backend 의존성이 낮고, 사람이 배워야 할 언어를 늘리지 않기 위해서입니다. 쿼리 결과와 update 실행 시간을 tabular 파일로 정렬해 triplestore 간 textual diff도 가능하게 합니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 조리법의 마지막에 “완성된 국은 소금 농도가 이 범위여야 한다”는 맛보기 표를 붙이는 것입니다. 작은 예: coherence 쿼리가 한 행이라도 반환하면 데이터 결함으로 실패합니다. 논문 대응: 같은 SPARQL 파일이 CI 검증, 웹 예시, MCP 기반 AI 문서가 됩니다.

04Use Cases · 사례

분산 데이터의 장기 진화와 의미 조정을 지원한다

한눈에 요약

첫 사례 ENPKG는 1,600개 식물 추출물, 100만 개 이상의 LC-HRMS/MS 스펙트럼을 통합하고 최종 6.4억 triples로 성장했습니다.

두 번째 ReconXKG는 VMH2, MetaNetX, UniProt, Rhea 등을 대사 네트워크로 조정하는 진행 중 사례입니다.

저자들은 단순한 import보다 “공동체가 각자 graph를 재동기화하면서 의미와 데이터가 계속 바뀌는 상황”을 주요 평가 대상으로 봅니다.

Sinergia 프로젝트에서는 private consortium data와 public reference를 함께 관리했고, MetaboT는 이 그래프의 curated SPARQL 예시를 이용해 50개 질문 중 83.7%를 맞혔다고 보고된 후속 시스템입니다. ReconXKG에서는 서로 다른 RDF 구조·어휘를 SPARQL UPDATE와 named graph 단계로 분리해 reconciliation을 진행합니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 여러 연구실이 각자 만든 사전을 하나의 다국어 사전으로 합치는 일입니다. 작은 예: 같은 대사물질을 서로 다른 ID로 부르는 데이터를 중간 reconciliation graph에서 연결합니다. 논문 대응: derived dataset과 SPARQL update가 의미 정렬 단계를 명시적으로 보존합니다.

05Practice · 적용 조건

재현 가능한 데이터 파이프라인이지만, 원격 헤더와 순차 실행을 믿어야 한다

한눈에 요약

장점은 선택적 rebuild, Git diff, 여러 triplestore, 검사 가능한 중간 graph입니다.

주의점은 원격 서버가 헤더를 부정확하게 주면 변경을 놓치고, 선언 순서 기반 단일 pass는 병렬 실행보다 단순하지만 느릴 수 있다는 점입니다.

kgsteward는 범용 lakehouse 엔진이라기보다 RDF·SPARQL 중심의 versioned data stewardship 도구입니다.

실무 도입 시에는 원격 소스의 ETag/내용 해시 보강, checksum 변경으로 인한 cascade rebuild 비용, frozen dataset의 신선도 책임, triplestore별 SPARQL 차이를 확인해야 합니다. 코드는 GitHub에 공개돼 있고 GPL-3.0입니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 자동 재고 시스템이 편리해도 납품업체의 송장 날짜가 틀리면 바뀐 물건을 놓칠 수 있습니다. 작은 예: URL의 Content-Length가 그대로면 파일 내용이 바뀌어도 rebuild하지 않을 수 있습니다. 논문 대응: 저자들은 원격 헤더 의존성과 큰 graph의 재계산 비용을 명시적 한계로 둡니다.
