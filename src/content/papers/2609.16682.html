01Motivation · 문제

문제와 QAD

한눈에 요약

고정 quota는 bursty workload를 따라가지 못해 GPU가 비어도 queue가 길어진다. DeepShare는 tenant가 보장량을 얼마나 회복했는지 나타내는 EMA 기반 QAD를 정의한다.

58-node·219-GPU cluster telemetry에서 평균 GPU utilization 19.8%, memory utilization 18.5%였다. QAD는 under-service를 오래 겪은 tenant의 recovery priority를 높이고 일시적 idle에는 과민 반응하지 않는다.

04Evaluation · 평가

05Assurance · 보장

quota와 ablation

한눈에 요약

DeepShare는 평균 Qi(t)=1.0과 낮은 queue를 함께 달성했다. QAD를 제거하면 utilization은 비슷해도 QoS와 queue가 악화된다.

Table VII에서 DeepShare queue는 1,168초였다. QAD 의존 결정을 모두 제거하면 QoS compliance 약 66%, worst-tenant QAD 0.81, guaranteed queue 약 1,600초가 된다.

06Deployment · 배포

물리 클러스터와 한계

한눈에 요약

16-A100 Kubernetes testbed에서 50 job을 실행해 Hard baseline 대비 makespan 32%, JCT 34%, queue 66%를 줄이고 93% QoS compliance를 유지했다.

대학 규모 trace·합성 quota·runtime prediction에 의존하므로 다른 cluster 규모와 provider policy에서 같은 trade-off인지 검증해야 한다.

＋Glossary · 핵심 용어

핵심 용어 정리

QADQuota Assurance Degree

tenant 보장 quota 회복 정도.

DRADeficit-aware Reclaimable Allocation

유휴 quota를 빌려주고 필요하면 회수하는 정책.

best-effort최선 노력 작업

보장 밖 여유를 쓰며 preempt될 수 있는 작업.

MPS colocationGPU 공유 실행

여러 작업을 한 GPU에서 동시 실행.

tenant-cycle QoS주기 보장

스케줄 cycle마다 tenant 보장이 지켜지는 비율.
