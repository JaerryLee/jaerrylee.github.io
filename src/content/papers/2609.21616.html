01Problem · 라벨의 출발점

결함 예측은 bug-fix 라벨의 품질을 물려받는다

한눈에 요약

SZZ와 결함 예측은 어떤 commit이 bug fix인지 먼저 알아야 하지만, issue link·issue type·키워드 모두 누락과 잡음을 가집니다.

저자들은 commit message와 bounded diff를 로컬 모델에 주어 issue tracker 없이 재현 가능한 binary label을 만들고자 합니다.

라벨이 틀리면 그 뒤의 bug-introducing commit, defect predictor, benchmark까지 같은 오류를 상속합니다.

파이프라인은 저장소를 clone하고 commit history를 순회하며, 최대 10개 파일·파일당 50줄로 diff를 제한합니다. temperature 0, top-p 0, top-k 1로 deterministic inference를 사용해 같은 입력에서 같은 라벨이 나오게 했습니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 시험 문제의 정답표가 틀리면 그 정답표로 학습한 모든 모델이 함께 틀립니다. 작은 예: “fix”라는 단어가 있어도 버전 bump면 버그 수정이 아닙니다. 논문 대응: 모델은 메시지보다 실제 diff의 주된 목적을 보도록 지시받습니다.

02Method · 데이터와 prompt

7개 로컬 모델과 두 prompt를 같은 조건에서 비교한다

한눈에 요약

P1은 zero-shot, P2는 더 엄격한 제외 규칙과 6개의 예시를 포함하며 precision 쪽으로 operating point를 이동시킵니다.

평가 corpus는 BugsInPy·PyBugHive·BugsJS(positive-only)와 SmartSHARK(Java positive+negative)입니다.

모델 규모가 커질수록 항상 좋아지는지와 prompt가 결과를 얼마나 움직이는지를 분리해서 봅니다.

모델은 약 7B부터 122B까지, 일반·code-specialized 쌍을 포함합니다. 출시 corpus는 권장 모델 mistral-small3.2:24b + P2로 33개 open-source 프로젝트, 389,567 commits를 라벨링했습니다. SmartSHARK는 39개 프로젝트 중 34개가 issue type을 수작업 검증했고, 링크되지 않은 실제 fix가 negative로 잡힐 수 있어 precision은 보수적 하한입니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 같은 시험을 여러 학생에게 주되, 문제 설명만 조금 바꿔 점수가 얼마나 달라지는지 보는 실험입니다. 작은 예: P2는 “테스트만 바꾼 commit은 fix가 아님”을 예시로 보여 줍니다. 논문 대응: 모델·prompt·언어·프로젝트를 고정·분리해 비교합니다.

03Evaluation · benchmark validity

negative 예시가 없으면 과하게 fix라 해도 높은 점수를 받는다

한눈에 요약

positive-only corpus에서는 false positive를 셀 수 없어 F1이 사실상 recall만 반영합니다.

따라서 SmartSHARK를 precision·recall·F1의 주 평가로 삼고, 저장소를 block으로 하는 Friedman/Nemenyi 검정을 사용했습니다.

BugsInPy, BugsJS, PyBugHive에서 거의 모든 commit을 fix라 부르는 모델이 상위로 보일 수 있다는 것이 이 논문의 중요한 방법론적 결과입니다.

저자들은 repository별 F1을 macro-average하고, 모델 간 비교를 같은 repository 안의 rank로 수행했습니다. positive-only corpus는 “놓치지 않는가”만 말해 주며 “얼마나 헛되게 fix라 부르는가”를 말해 주지 못합니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 골대가 하나뿐인 게임에서는 공을 아무 데나 차도 “시도했다”고 점수를 받는 것과 같습니다. 작은 예: negative commit이 없으면 모든 commit을 fix라 해도 false positive가 보이지 않습니다. 논문 대응: precision-aware benchmark에는 반드시 negative 예시가 필요합니다.

04Results · 모델과 prompt

큰 모델보다 prompt와 데이터 구성이 operating point를 좌우한다

한눈에 요약

SmartSHARK 34개 검증 프로젝트에서 P1의 최고 평균 F1은 mistral-small3.2:24b 0.645, P2는 0.644였습니다.

P1은 recall이 높고 P2는 precision이 높아졌으며, P2에서는 상위 5개 모델이 통계적으로 구분되지 않는 군을 이뤘습니다.

모델 파라미터 수가 최대인 qwen3.5:122b가 일관되게 최고가 아니었습니다. 로컬에서 실행 가능한 중간 규모 모델도 충분한 후보입니다.

P1의 34개 프로젝트 평균은 mistral precision 0.572, recall 0.751, F1 0.645였습니다. P2에서는 precision 0.588, recall 0.724, F1 0.644로 이동했습니다. qwen3.6:35b는 P2 precision 0.634로 가장 높았습니다. repository별 변동은 크므로 평균만으로 배포 결정을 내리면 안 됩니다.

비유: 큰 엔진 자동차가 좁은 골목에서 항상 가장 빠르지는 않습니다. 작은 예: 작은 모델도 prompt와 negative 예시를 잘 받으면 키워드보다 나은 F1을 냅니다. 논문 대응: parameter count보다 corpus 구성·prompt·repository 특성이 결과를 좌우합니다.

05Limitations · 활용

silver standard는 강한 baseline이지만 ground truth가 아니다

한눈에 요약

키워드 baseline은 validated corpus에서 fix의 절반도 회수하지 못했고, 로컬 모델은 대체로 더 많은 fix를 찾았습니다.

그러나 diff를 10파일·파일당 50줄로 자르고, SmartSHARK precision은 issue link 편향을 포함하며, released corpus 자체도 모델 생성 라벨입니다.

실무에서는 SZZ seed나 프로젝트별 defect dataset을 만들 때 로컬·결정적 labeling pipeline을 사용할 수 있지만, 샘플 수작업 검수와 negative 설계가 반드시 필요합니다.

두 prompt의 차이는 여러 요소가 동시에 바뀌어 단일 요인의 인과를 주장할 수 없습니다. Java 이외 언어의 precision을 직접 평가할 negative corpus가 없고, 실험은 두 대여 L40 GPU에서 수행됐습니다. 다음 단계는 실제 프로젝트별 human audit, 큰 diff 처리, hosted frontier model과 재현성 비용의 비교입니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 은메달은 금메달보다 낫다는 뜻일 수 있지만 완벽한 정답표는 아닙니다. 작은 예: 모델이 fix라고 붙인 79,696개 commit 중 일부는 사람이 다시 확인해야 합니다. 논문 대응: 저자들은 결과 corpus를 silver standard라고 명시하고 measured error를 함께 공개합니다.
