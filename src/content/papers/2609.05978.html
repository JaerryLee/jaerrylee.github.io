01Motivation · 동기

runnable test와 adequate test 사이의 간극

한눈에 요약

테스트가 실행되고 coverage가 높아도 assertion이 무의미하거나 중요한 실패 경로를 빠뜨릴 수 있다. VibeCheck은 “돌아간다”와 “행동을 검증한다”를 분리해 보자고 제안한다.

저자들은 인증·권한·DB 같은 정상 경로만 검사하고 잘못된 자격 증명, 세션 만료, 외부 의존성, 경계값을 놓치는 전형적인 실패를 지적한다. 테스트는 실행 가능한 문서이므로, 배포 전에는 실행 성공보다 어떤 개발자 의무(behavioral obligation)를 실제 assertion으로 확인했는지가 중요하다.

초등학생도 이해하는 설명

숙제를 제출했는데 파일이 열리는 것만으로 정답이라고 할 수 없다. 내용이 맞는지 확인하는 문제가 따로 있다.

02Method · 방법

15개 저장소·4개 생성기·5차원 rubric

한눈에 요약

Kiro·Antigravity·Cursor와 standalone Claude Sonnet 4.5가 15개 학생 Python·JavaScript/TypeScript 저장소에서 zero-shot·repository-only로 테스트를 만들었다. 각 결과는 R1 runnability, R2 assertion strength, R3 logic/edge coverage, R4 isolation/determinism, R5 maintainability로 채점했다.

각 테스트 스위트는 자기 자신을 평가하지 않는 leave-one-out 방식으로 나머지 세 agent가 JSON 보고서를 만든다. 평가자는 blocking error·flakiness·weak assertion·missing behavioral case와 수정 제안을 함께 기록하고, 저장소에서 도출한 developer-defined obligation을 만족하는지 별도로 확인한다.

03Results · 결과

Kiro는 파일 범위, Claude는 테스트 밀도가 앞선다

한눈에 요약

Kiro는 15개 저장소 중 10개에서 최고 점수였고, 182개 파일로 파일 범위는 가장 넓었다. 반면 standalone Claude는 83개 파일에 2,848개 케이스를 넣어 케이스 밀도와 maintainability에서 강점을 보였다.

Kiro는 R1–R3 평균이 각각 4.41·4.37·4.52로 가장 높았고, R5 maintainability는 Claude 4.5가 1.71로 Kiro 0.83보다 높았다. Antigravity와 Cursor는 파일·케이스 수가 적었고, 저장소별 최선은 고정되지 않아 harness와 프로젝트 구조의 상호작용이 컸다.

04Diagnostics · 진단

약한 assertion과 누락된 행동이 가장 흔하다

한눈에 요약

missing behavioral case는 네 생성기 모두에서 가장 흔한 실패 신호였다. confidence와 실제 품질의 Pearson r은 0.21로 약해, 자신 있게 말한 평가가 좋은 평가라는 보장이 없었다.

대표적인 실패는 예외가 발생해야 하는 코드에서 try/catch만 하고 assertion을 실행하지 않는 테스트다. 이런 테스트는 함수가 예외를 던지지 않아도 통과할 수 있다. Table 4에서 Kiro는 runnability·assertion·logic 점수가 높지만, isolation과 maintainability는 별도의 개선이 필요하다.

한 줄 결론

AI 테스트 평가는 pass/fail과 coverage를 넘어 “무엇을 검증했는가”를 먼저 물어야 한다.

초등학생도 이해하는 설명

겉으로 초록불이 켜져도 버튼을 눌러야 할 때 눌렀는지, 잘못 눌렀을 때 멈추는지 확인해야 한다.

05Limits · 한계

학생 저장소·단일 모델·LLM peer judge의 범위

한눈에 요약

실험은 학생 저장소 15개, Claude Sonnet 4.5 하나, human gold label 없는 cross-agent LLM 평가에 의존한다. 따라서 산업 규모 저장소와 여러 모델에서 같은 패턴이 재현되는지는 아직 열린 질문이다.

논문은 zero-shot·repository-only라는 통제 덕분에 재현 가능하지만, few-shot·iterative repair·외부 문서·mutation score를 비교하지 않았다. 또한 Kiro의 우수성은 모델 자체보다 harness 차이일 수 있고, 평가자 confidence는 실제 품질 대리 지표로 쓰기 어렵다.

초등학생도 이해하는 설명

작은 운동장에서 잘한 선수라고 큰 경기장에서도 똑같이 잘한다고 단정할 수 없다. 그래도 어떤 항목을 점검해야 하는지에 대한 체크리스트는 바로 쓸 수 있다.

＋Glossary · 핵심 용어

핵심 용어 정리

behavioral obligation행동 의무

개발자가 테스트로 반드시 확인해야 한다고 정한 기능·예외·경계 조건.

runnability실행 가능성

import·fixture·설정 오류 없이 테스트가 실행되는 정도.

assertion strength검증 강도

단순 non-null이 아니라 실제 결과·상태를 검증하는 정도.

leave-one-out review교차 평가

생성한 agent가 자기 결과를 채점하지 않고 다른 agent가 평가하는 방식.

flakiness불안정성

시간·random·네트워크·공유 상태에 따라 결과가 흔들리는 위험.
