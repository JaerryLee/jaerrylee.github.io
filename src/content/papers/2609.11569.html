01Background · 배경

LLM에게 지식 그래프의 사용 설명서를 먼저 건넨다

한눈에 요약

EXYGEN은 자연어 질문을 SPARQL로 바꾸는 KG 질의 시스템이다. 그래프 전체를 LLM 프롬프트에 넣지 않고, 구조 요약과 작은 triple 샘플을 검색해 제공한다.

정말 쉽게 한 문장

도서관 책장을 통째로 외우게 하지 말고, 책장 규칙과 관련 예시 몇 개를 먼저 보여준 뒤 질문을 SQL처럼 바꾸게 한다.

초등학생도 이해하는 설명

“누가 누구의 선생님이야?”라는 질문에 책장 전체를 주는 대신, 라벨 붙은 책장 지도와 관련 책 몇 권만 보여주는 것이다.

그래프의 ‘무엇이 어떻게 연결되는가’를 알려주는 구조 컨텍스트가 핵심이다.

저자들은 VoID 통계, ShEx 모양(schema), 검색된 RDF triple, 질문–쿼리 예시(QQP)를 별도 인덱스에 저장해 질의 때 필요한 조각만 붙인다.

02Method · 방법

ShEx는 그래프의 문법책, QQP는 풀이 예시다

한눈에 요약

VoID는 클래스·predicate 통계를, ShEx는 각 클래스가 가질 수 있는 속성·개수·값 타입을 사람이 읽기 좋게 표현한다. QQP는 실제 질문과 SPARQL 쌍으로 사용법을 보여준다.

초등학생도 이해하는 설명

ShEx는 “학생에게는 이름표가 꼭 하나 있어야 한다” 같은 문법책이고, QQP는 선생님이 푼 문제 한두 개다.

질문은 Qwen3-Embedding-0.6B로 벡터화하고, ChromaDB에서 각 컨텍스트 유형별 top-k를 따로 검색한다.

중요한 점은 컨텍스트를 한 바구니에 섞지 않는 것이다. schema와 triple과 예시를 각각 알맞은 granularity로 뽑아 LLM 입력에 이어 붙인다.

03Results · 결과

실행 가능성과 정답은 다른 문제였다

한눈에 요약

ShEx만 넣어도 큰 모델의 실행률은 0.97 이상이었지만 EMRelEx는 0이었다. DeepSeek-V3.1에 VoID+ShEx+검색 triple+QQP를 모두 넣었을 때 실행 결과 EMRelEx가 0.419로 최고였다.

초등학생도 이해하는 설명

문장이 문법에 맞게 쓰였다는 것과, 문제의 정답을 맞혔다는 것은 다르다. 숙제 문장이 말이 돼도 답이 틀릴 수 있다.

논문이 강조하는 교훈은 쿼리 글자 모양 F1만 보고 성공했다고 말하면 안 된다는 것이다.

대표 사례에서 F1=0.9464인 쿼리도 prefix 이름이 달라 실행에 실패했다. QQP가 정답에 크게 기여했지만, Qwen2.5-3B는 QQP를 넣자 실행률이 거의 0으로 떨어지는 등 모델 규모와 컨텍스트 조합의 상호작용도 컸다.

04Scaling · 확장

그래프가 커질수록 전체를 읽지 말고 대표 샘플을 읽는다

한눈에 요약

VoID·ShEx 생성은 full-scan SPARQL 집계 때문에 느리거나 timeout이 난다. EXYGEN은 predicate가 골고루 나타나도록 병렬 random walk와 의미/degree 기반 이웃 선택을 사용한다.

초등학생도 이해하는 설명

도시의 모든 집을 방문하지 않고, 동네마다 대표 집을 골라 주소 체계가 어떤지 알아내는 방식이다.

두 홉 random walk가 비용과 coverage의 균형이 좋았고, OCM에서는 semantic similarity <0.6가 2.41분에 76.64% predicate coverage를 달성했다.

GESIS는 97.52M triple의 0.42%만 샘플해도 metadata 생성 시간이 19분 21초에서 13.77초로 줄었다. ORKG는 triple 수보다 세밀한 ontology 조합이 문제라 전체 생성이 불가능했고 18% 샘플이 유일한 실행 경로였다.

05Limits · 한계

예시가 없으면 schema만으로는 정답까지 못 간다

한눈에 요약

EXYGEN은 fine-tuning 없이 구조화 컨텍스트가 실행 가능성을 높인다는 점을 보였지만, SciQA 하나의 벤치마크에 의존하고 curated question-query examples가 여전히 결정적이다.

초등학생도 이해하는 설명

문법책만 주면 문장은 만들 수 있지만, 실제 문제를 푸는 예시가 있어야 어떤 답을 써야 하는지 배운다.

샘플링은 그래프를 이해하기 위한 metadata를 싸게 만드는 장치이지, 그래프의 모든 사실을 보존하는 검색 인덱스와 같은 것은 아니다.

저자들은 synthetic exemplar 생성이나 실행 피드백을 이용해 QQP 의존을 줄이는 후속 연구를 제안한다. 또한 논문에 직접 확인된 소속은 모두 Odoma Ltd.이며, 연구 결과를 다른 KG·LLM·endpoint로 일반화하려면 별도 검증이 필요하다.

검색 경험칙

ShEx·VoID·retrieved triples·question-query pairs가 보이면 ‘그래프의 구조를 알려주는 KG-RAG’다. HNSW/Vamana만 보이면 지식 그래프가 아니라 벡터 검색 내부 인덱스일 가능성이 높다.

클래스별 속성·값 타입·카디널리티를 표현하는 KG schema 언어.

SPARQLSPARQL

EMRelExExecution-based Exact Match Relaxed

생성 쿼리를 실제 실행한 결과 집합이 정답과 같은지 비교하는 지표.

Predicate coveragePredicate coverage
