01Problem · fragmentation

CPU와 메모리를 고정 번들로 묶으면 남는 자원이 있어도 다음 함수를 넣지 못한다

한눈에 요약

Huawei production trace에서 median CPU 이용률 20%, memory 16%이며 90% 이상 allocation이 provisioned capacity 55% 미만을 사용합니다.

CPU·memory를 이상적으로 독립 배치하면 내부 낭비는 줄지만 residual shape가 다양해져 node 외부 단편화가 78% memory·44% CPU까지 올라갑니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 큰 상자에 물건을 담을 때 남은 공간이 있어도 모양이 안 맞으면 새 상자를 여는 상황입니다. 작은 예: CPU 2개와 메모리 4GB가 남았지만 다음 함수가 CPU 1개·메모리 6GB라면 못 넣습니다. 논문 대응: Memoryless는 다양한 모양의 variant를 만들어 빈 공간을 채웁니다.

02Method · control plane

locality를 고정 속성이 아니라 scheduler가 조절하는 variant로 만든다

한눈에 요약

Elastic Memory Ratio(EMR)는 footprint 중 local DRAM으로 보장할 비율입니다. EMR 1.0은 fully local이고 낮출수록 remote pool을 허용합니다.

Configuration Discovery가 vCPU·worker·EMR 조합을 측정해 Pareto frontier를 만들고, Capacity Planning/Placement가 residual node 자원에 맞춰 조합을 선택합니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 택시가 승객마다 좌석 수·짐칸·고속도로를 조절하듯 함수마다 자원 모양을 바꿉니다. 작은 예: memory-intensive 함수는 local 60%·remote 40% variant를 골라 CPU 여유를 다른 함수에 줍니다. 논문 대응: EMR이 locality를 control-plane knob로 승격합니다.

03Placement · runtime

SLO를 지키면서 variant 수와 위치를 함께 고른다

한눈에 요약

각 variant는 tail latency, sustainable throughput, vCPU, local memory, total memory footprint를 갖습니다. latency가 SLO를 넘는 variant를 먼저 제거하고, aggregate goodput이 요청률을 넘도록 replica 수를 정합니다.

Algorithm 1의 scale-out/in은 Δλ, residual capacity, queue length와 variant metadata를 이용해 재배치·라우팅합니다.

생활 속 비유 · 작은 예 · 논문 대응

비유: 창고 관리자가 주문량뿐 아니라 선반의 남은 칸 모양을 보고 물건 크기를 고르는 것입니다. 작은 예: 빈 CPU 1.5개·local memory 0.5GB에 맞는 variant를 선택해 새 서버를 켜지 않습니다. 논문 대응: allocation과 placement를 분리하지 않고 joint decision으로 처리합니다.

04Evaluation · 결과

node·CPU 낭비와 goodput을 줄이고, 온라인 결정 시간은 유지한다

한눈에 요약

Knative prototype과 실제 Huawei traces, trace-driven simulation, thumbnailer/video/graph/DNA 함수로 평가했습니다.

Memoryless는 steady node 최대 40%, peak 46% 감소, CPU stranding 44% 감소, SLO 위반은 3% 이내로 보고됩니다. Memoryless-LO는 ComboFunc보다 goodput 약 4%, EMR까지 쓰면 추가 18% 높았습니다.

05Trade-offs · 한계

효율을 얻는 대신 profiling·remote latency·churn을 운영해야 한다

한눈에 요약

Memoryless는 ComboFunc+보다 약 20–40% 높은 churn을 보일 수 있지만 약 35% 적은 node를 사용합니다. ILP oracle은 고부하에서 3분 timeout을 넘겨 online에 쓸 수 없습니다.

EMR은 함수별 workload-aware profiling이 필요하고, remote memory 민감도가 함수마다 달라 무조건 낮추면 안 됩니다.

＋Glossary · 핵심 용어

핵심 용어

Internal fragmentation내부 단편화

함수 allocation 안에 예약됐지만 쓰이지 않는 자원.

External fragmentation외부 단편화

노드에 남았지만 어떤 함수 shape에도 맞지 않는 자원.

EMRElastic Memory Ratio

메모리 footprint 중 local DRAM으로 처리할 비율.

Goodput지속 처리량

SLO를 지키며 실제로 처리 가능한 요청률.
