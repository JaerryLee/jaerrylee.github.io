01Motivation · 필요성

장기 과학 작업은 관찰·복구·재현이 필요하다

한눈에 요약

과학 워크플로는 데이터 수집→계산→해석을 여러 번 반복하고, 중간 모델·궤적·artifact를 다시 만드는 비용이 크다. 모델이 다음 tool-call을 선택하는 방식만으로는 세션이 끊겼을 때 무엇을 복구할지 알기 어렵다.

OpenAI4S는 “Code as Action, Science as Sessions”라는 원칙으로, 과학적 조작을 완전한 Python/R 코드 셀로 실행하고 연구 에피소드를 session으로 보존한다. 목표는 최종 답변보다 연구자가 결과를 검사하고 이어서 실행할 수 있는 기록을 남기는 것이다.

02Architecture · 구조

control plane과 persistent science runtime의 dual plane

한눈에 요약

control plane은 권한·메타데이터·서비스를 JSON tool call로 다루고, science runtime은 지속 Python/R kernel에서 완전한 code cell을 실행한다. 두 평면은 하나의 dispatcher와 shared state를 통해 연결된다.

Python cell은 host.llm·delegate·save_artifact·compute 같은 감사된 host service를 동기 RPC로 호출할 수 있다. model이 파일 하나를 읽을 때마다 왕복하는 대신 셀 안에서 여러 작업을 묶고, 실행 관찰은 한 번 반환한다. 다만 kernel namespace는 재시작 후 그대로 살아나지 않으므로 durable file·artifact·checkpoint가 필요하다.

초등학생도 이해하는 설명

작은 심부름 열 개를 열 번 왕복하지 않고, 한 장의 작업지시서 안에서 순서대로 처리한 뒤 결과와 증거를 함께 돌려준다.

03Provenance · 기록

ledger·artifact·environment·checkpoint가 세션을 만든다

한눈에 요약

각 action group과 cell은 입력·출력·상태·토큰 비용·파일·환경을 기록하고, artifact는 SHA-256과 producing cell에 연결된다. 세션 package는 ledger·notebook·snapshot·environment·lineage를 해시 manifest와 함께 내보낸다.

Action Ledger는 append-only이지만 세션 삭제는 기록을 지울 수 있다. checkpoint는 best-effort이고, recovery는 안전하다고 판단한 셀만 replay하므로 “복구 시도”와 “완전 복원”을 구분한다. Python AST 기반 namespace 의존성과 선택적 live lineage는 보수적 추정이므로, 관측되지 않은 읽기까지 자동으로 추적한다고 약속하지 않는다.

04Evaluation · 평가

36 시나리오에서 delivery와 lower tail을 비교한다

한눈에 요약

6개 과학 task·36개 scenario에서 OpenAI4S macro score는 7.83으로, Claude Code 기반 Kimi 5.79·GLM 6.36·Opus 6.12보다 높았다. paired 31개 시나리오에서 5점 미만 비율은 OpenAI4S 6.5%로 기준선 45.2–61.3%보다 낮았다.

05Safety · 안전

sandbox·permission·screening의 경계

한눈에 요약

OpenAI4S는 OS sandbox, permission broker, code/trajectory screening, egress allowlist를 조합하지만 모든 기능이 항상 켜지는 것은 아니다. 실패 처리도 보수적이지 않은 경로가 있어 설정과 운영 모드의 기록이 중요하다.

sandbox가 자동 모드에서 성립하지 않으면 degraded 상태로 계속할 수 있고, biosecurity screener는 BLOCK일 때만 실행을 막는다. retrieved content injection screening과 권한 승인은 감사 흔적을 남기지만, prompt-level 정책이 과학적 진실성이나 보안을 형식적으로 증명하지는 않는다.

초등학생도 이해하는 설명

문에 자물쇠가 여러 개 있어도 어떤 자물쇠가 실제로 잠겼는지 확인해야 한다. 설정값과 실패 시 행동까지 기록해야 안전을 설명할 수 있다.

06Limits · 한계

환경 재구성과 과학적 진실성은 아직 미완성

한눈에 요약

모든 시스템에서 environment specification과 완전한 rerun은 약한 점으로 남았다. 메모리 객체는 재시작 후 사라지고, replay는 안전하게 판정된 셀만 복원하며, lineage도 관측 범위에 한정된다.

비교는 모델·prompt·tool·compute가 맞춰진 ablation이 아니라 complete system 비교이므로 특정 구성요소의 인과 효과를 말할 수 없다. 논문은 다른 머신에서 manifest로 환경을 재구축하고, matched harness와 독립 scientific review로 검증하는 일을 후속 과제로 제시한다.

한 줄 결론

정확한 계산·완전한 workflow·재현 가능한 증거를 별도 축으로 보존해야 장기 agent가 연구 인프라가 된다.

초등학생도 이해하는 설명

실험 결과를 복사해 주는 것과, 누가 언제 어떤 도구로 만들었는지 다시 확인할 수 있게 하는 것은 다른 일이다.
