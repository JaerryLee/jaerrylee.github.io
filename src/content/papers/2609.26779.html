01Problem · 문맥 관리

긴 궤적에서 모든 기록을 보존하면 비싸고, 계속 요약하면 의미가 흐려진다

한눈에 요약

코딩 에이전트는 수백만 토큰의 도구 호출과 결과를 누적합니다. 슬라이딩 윈도우는 캐시를 계속 무효화하고, 요약의 요약은 정보가 조금씩 변합니다.

CliffCompaction은 전체 이력 회상보다 최근 기록의 문자 그대로의 정확도(compaction precision)를 우선합니다.

핵심 설계는 “오래된 기록을 잘 요약하는 모델”이 아니라 “오래된 기록을 다시 만들지 않고 필요한 부분만 다시 읽을 수 있게 하는 규칙”입니다.

논문은 tool result가 전체 토큰의 56%, tool call이 28%라서 둘을 먼저 줄입니다. 시스템 프롬프트와 최초 작업 설명은 보존하고, 최근 K turn은 그대로 남깁니다. 500자 이하 결과는 유지하고 긴 결과는 호출 서명만 남겨 파일·경로를 다시 읽을 수 있게 합니다.

비유: 책 전체를 매번 복사하지 않고 최근 장을 원문으로 보관하며 오래된 장은 “몇 쪽에 무엇이 있다”는 목차만 남깁니다. 작은 예: 긴 로그 결과를 버려도 파일 경로와 명령은 남아 다시 실행할 수 있습니다. 논문 대응: CliffCompaction은 회상을 포기하는 대신 보존 구간의 왜곡을 줄입니다.

02Method · 알고리즘

임계점에서만 절벽처럼 줄이고, 과거 압축을 절대 다시 압축하지 않는다

한눈에 요약

컨텍스트가 임계 B를 넘으면 old와 recent를 나눕니다. old의 이전 압축 블록은 건너뛰고, 생각은 300자로 자르고, tool call은 약 150자의 서명으로, 짧은 결과만 남깁니다.

새 압축 C_t는 직전 라이브 구간 L_t에서만 만들고 C_{t-1}은 버립니다. 따라서 요약의 요약이 누적되지 않습니다.

알고리즘의 비용 절감은 빈번한 편집을 피하는 데서 나옵니다. 문맥이 자연스럽게 자랄 때는 캐시를 계속 재사용하고, 임계점을 넘을 때만 작은 새 문맥을 prefill합니다.

압축 순간마다 KV-cache가 무효화되는 비용은 피할 수 없지만, 압축된 문맥이 훨씬 작고 이벤트가 드물어 긴 구간의 cache hit로 상쇄됩니다. API proxy로 구현되어 scaffold와 모델을 가리지 않습니다.

03Evaluation · 벤치마크

짧은 코드 수정부터 백만 토큰 커널 최적화까지 성능을 유지한다

한눈에 요약

SWE-bench Verified, Terminal-Bench 2.0/2.1을 mini-swe-agent, OpenHands, Terminus-2, Claude Code proxy에서 평가했습니다. 임계값은 8K·16K·32K·45K 등입니다.

KernelBench Level 3에서는 L40S와 RTX Pro 6000에서 200·400 step을 비교해 지속 학습 효과를 측정했습니다.

저자의 측정에서 압축은 전체 문맥보다 작지만 해결률을 유지하거나 높였습니다. 단, 모델·scaffold·가격표·하드웨어가 명시된 실험 결과로 읽어야 합니다.

04Scaling · 결과

압축으로 여러 번 시도하는 비용을 감당하고, 커널 탐색을 더 오래 지속한다

한눈에 요약

Terminal-Bench에서 Kimi K2.6 16K 문맥으로 3회 rollout은 69.7%, $58.01이며 GPT-5.3 Codex 단일 실행 비용보다 낮습니다.

KernelBench에서 Kimi K2.7은 200 step 2.23×, 400 step 3.58×를 기록했습니다. 무압축은 256K 한계에 걸려 1.30×에서 멈췄습니다.

실험은 단순히 토큰을 줄인 것이 아니라, 같은 비용으로 더 많은 독립 시도와 더 긴 순차 탐색을 살 수 있음을 보입니다.

05Limitations · 운영

회상 손실과 선택기 의존성을 숨기지 않고 도입해야 한다

한눈에 요약

CliffCompaction은 두 번의 압축 이후 직접적인 과거 이력을 버리므로 full-history recall이 낮습니다. 에이전트가 간접적으로 기억을 전달한다는 residual propagation이 있지만 보장은 아닙니다.

가격은 API provider 측정과 특정 하드웨어·모델 조합에 의존하며, SGV selector는 별도 학습 데이터와 누수 점검이 필요합니다.

긴 에이전트에 적용할 때는 “삭제된 파일 내용을 다시 찾아야 하는가”와 “요약이 필요한 회의형 작업인가”를 분리해 판단해야 합니다.

논문 부록은 token/cost attribution, provider cache hit, 가격, wall-clock, selector feature, same/cross-model 학습, data efficiency와 추가 KernelBench trace를 제공합니다. 요약의 정밀도와 회상 범위를 운영 지표로 따로 기록해야 하며, 모든 에이전트·모델에 같은 비용 개선을 가정하면 안 됩니다.
