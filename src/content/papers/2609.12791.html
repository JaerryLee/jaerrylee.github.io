01Motivation · 동기

전역 지식공간은 길이 많고 표지판이 틀릴 수 있다

한눈에 요약

작은 oracle 문서만 쓰는 기존 평가와 달리 CoG는 5B 단어 텍스트와 115M entity·1.7B triple 규모의 전역 공간을 가정한다. 이 환경에서는 계획·entity 모호성·막힌 길 회복이 필요하다.

그래프를 한 번 따라가는 것보다 “어디부터 조사하고, 지금까지 충분한가, 다음에 어느 방향으로 돌아갈까”가 중요하다.

VectorRAG는 텍스트 chunk를 가까운 순서로 찾고, 기존 GraphRAG 계열은 entity·relation을 따라간다. CoG는 그래프만 믿지 않고 해당 entity의 Wikipedia 문서를 읽어 새 entity를 발견한 뒤 그래프 탐색을 다시 안내한다.

초등학생도 이해하는 설명

동네 지도에서 목적지를 찾는데 길 이름이 비슷하고 어떤 길은 막혀 있다고 하자. CoG는 출발 전에 계획을 세우고, 길을 가 보고, 막히면 다른 길로 돌아가며, 길가의 글에서 새 장소 이름을 발견해 다시 지도에서 찾는다.

02Method · 방법

그래프와 텍스트가 서로를 안내한다

한눈에 요약

CoG는 네 단계를 고정 순서로 한 번 실행하지 않고, 반성 결과에 따라 반복한다. 텍스트에서 찾은 entity가 그래프의 새 anchor가 되고, 그래프 관계가 텍스트 읽기 방향을 좁힌다.

이 양방향성이 단순히 KG와 text를 함께 넣는 것과 다른 핵심이다.

Planning은 질문을 분석해 독립적인 sub-query와 anchor entity를 만든다. Exploration은 (1) vector recall + LLM disambiguation, (2) relation 선택, (3) fact pruning으로 KG 범위를 좁히고, 동시에 문서를 page selection→global skim→section detailed reading 순으로 읽는다. Synthesis는 두 출처를 하나의 summary로 모으고, Reflection은 continue 또는 strategy adjustment를 선택한다.

장기 상태는 검증된 사실을 쌓는 Notebook N, 나중에 다시 볼 Candidate Entity Pool P, 전체 전략을 보는 Interaction History H다.

초등학생도 이해하는 설명

지도와 책을 따로 보는 것이 아니라, 책에서 새 장소를 찾으면 지도에 표시하고, 지도에서 연결된 장소를 알면 책의 해당 장을 다시 읽는다.

04Analysis · 분석

한눈에 요약

05Limits · 한계

CoG는 강력하지만 값싼 검색은 아니다

한눈에 요약

계획·반성·텍스트 읽기·entity linking을 반복해 복잡한 전역 질문을 풀지만 latency와 token 비용이 증가한다. 작은 모델의 비용-정확도 절충은 유망하나 더 많은 환경 검증이 필요하다.

실무에서는 모든 질문을 CoG로 보내기보다, 낮은 확신·다중-hop·KG 단절 신호가 있을 때만 승격하는 것이 합리적이다.

한계로는 iterative latency·token cost, backbone LLM 의존성, global KG의 stale/noisy facts, source overlap 검증 범위가 있다. 논문은 CoG가 retrieval 자체를 없애지 않고, 더 적은 문서로 더 많은 탐색 판단을 하는 구조라고 설명한다.

검색 계열 1차 판별

분류: global hybrid GraphRAG / agentic graph-text exploration. KG entity·triple 관계를 따라가지만, 단순 PPR passage node(HippoRAG)도, Microsoft community report 중심 파이프라인도 아니다. HNSW·Vamana ANN 그래프는 entity linking vector recall의 보조 층이다.

초등학생도 이해하는 설명

길을 많이 돌아다니며 보물 위치를 확인하는 탐험가라서 어려운 문제에는 강하지만, 집 앞 편의점에 갈 때 쓰면 시간과 비용이 너무 많이 든다.

＋One-page Summary · 한 장 정리

이 논문을 한 장으로

01
결론: CoG는 global KG와 text를 계획·탐색·반성 순환으로 연결해 multi-hop QA 성능을 높였다고 보고한다.

정말 쉽게 한 문장: 지도와 책을 번갈아 보며 막힌 길은 돌아가는 똑똑한 보물찾기 검색이다.
