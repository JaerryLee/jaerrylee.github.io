01Background · 배경

재랭커는 같은 문서를 질문이 바뀔 때마다 다시 읽는다

한눈에 요약

검색기는 먼저 후보 문서를 넓게 찾고, LLM 재랭커는 질문과 각 문서를 함께 읽어 순서를 정교하게 고친다. 문제는 인기 문서가 여러 질문에 반복 등장해도 문서 토큰 계산을 매번 처음부터 한다는 점이다.

DoPR의 출발점은 문서 쪽 계산은 오프라인에 한 번 해두고 재사용할 수 없을까라는 질문이다.

일반 pointwise 재랭커는 각 쌍에 대해 s(q,d)=f([q;d])를 계산한다. 문서 d가 길거나 한 문서가 여러 질의 후보에 반복되면 입력 메모리와 attention 계산이 계속 중복된다. 단순 문서 요약이나 토큰 가지치기는 한 번의 입력을 줄이지만, 질의마다 문서를 다시 인코딩하는 문제는 남는다.

02Method · 방법

문서의 핵심 토큰을 여러 층의 KV prefix로 미리 저장한다

한눈에 요약

DoPR은 학습 때 문서 자체의 attention 신호로 핵심 토큰 K개를 고른다. 구조적 attention mask는 질의가 원문 전체를 직접 보지 못하고 선택된 표현을 통해서만 문서 정보를 받게 한다.

배포 시에는 선택된 표현을 모델 각 층의 key·value 상태로 변환해 문서별 prefix를 오프라인 저장한다.

온라인에서는 저장된 prefix와 새 질의·점수 토큰만 처리한다. prefix는 질의와 무관하므로 같은 문서가 다시 검색될 때 그대로 재사용된다. 학습 목표는 관련 문서가 비관련 문서보다 높은 점수를 갖게 하는 RankNet pairwise loss다.

03Effectiveness · 정확도

문서 토큰을 8분의 1로 줄여도 큰 모델에서는 순위 품질이 거의 유지됐다

한눈에 요약

04Efficiency · 효율

긴 문서와 반복 조회에서 오프라인 비용을 빠르게 상각한다

한눈에 요약

온라인 문서 표현 메모리는 고정 8배 줄었고, Covid에서 Qwen3-8B 지연시간은 150.708ms에서 18.743ms로 줄어 8.04배 빨라졌다. 짧은 DL19에서는 같은 모델의 속도 향상이 1.84배였다.

속도 이득은 모델 크기만이 아니라 원문 길이에 크게 좌우된다.

더 넓은 표 9에서는 길이 2,048 토큰인 Touche·News·Robust에서 8B 속도 향상이 약 18–19배지만, 192토큰 DBPedia에서는 1.81배다. 오프라인 prefix 생성 비용까지 포함하면 문서가 여러 질의에서 재사용될수록 평균 비용이 내려간다. 안정적인 기업 문서·상품 목록·논문 컬렉션에 잘 맞는 이유다.

05Ablations & Limits · 한계

효율은 공짜가 아니라 저장공간과 문서 재사용을 전제로 한다

한눈에 요약

attention 기반 Top-K 선택, 압축 없는 워밍업, 학습 prefix 수가 품질에 영향을 미쳤다. 고정 압축률은 주로 문서 토큰의 12.5%, 즉 8분의 1이다.

Llama-3.2-1B과 추가 12개 BEIR 데이터셋에서도 작동해 한 모델·몇 개 데이터셋에만 맞춘 결과는 아니었다.

하지만 문서가 자주 바뀌거나 한 번만 검색되는 환경에서는 prefix 생성·저장 비용을 회수하기 어렵다. 모델 버전이 바뀌면 다층 KV 상태도 다시 계산해야 하며, 전체 문서 원문보다 작은 prefix라도 대규모 컬렉션에서는 상당한 저장공간이 필요하다. 압축이 어떤 문서 부분을 선택하는지에 따른 편향·민감정보 보존 문제도 남는다.

한눈에 요약

논문의 주장을 따라가는 데 필요한 용어만 간결하게 모았다.

재랭킹Reranking

1차 검색 후보를 더 강한 모델로 다시 점수화해 순서를 고치는 단계.

PointwisePointwise reranking

각 질문–문서 쌍을 독립적으로 입력해 관련성 점수를 내는 방식.

KV cacheKey-value cache

Transformer 각 층에서 이미 계산한 attention key와 value를 저장해 다시 쓰는 상태.

문서 prefixDocument prefix

문서 핵심 표현에서 미리 만든 다층 KV 상태로, 질의 앞에 계산된 컨텍스트처럼 주입된다.

Top-K 선택Top-K selection

attention 점수가 큰 문서 토큰 K개만 골라 압축 표현으로 쓰는 방법.

NDCG@10Normalized Discounted Cumulative Gain

관련 문서가 상위 10개 안에서 얼마나 좋은 순서로 배치됐는지 평가하는 검색 지표.

상각Amortization

한 번 든 오프라인 비용을 여러 온라인 요청에 나눠 요청당 부담을 낮추는 것.
