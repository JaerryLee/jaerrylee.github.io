01Baseline · 기준선

코드에서 가까운 문장과 필요한 관계는 다르다

한눈에 요약

일반 RAG는 isolated chunk를 top-k로 가져온다. 의미 유사도는 비슷한 코드 줄을 찾을 수 있지만 상속·호출 관계를 보장하지 않는다.

코드 변환에서는 “비슷해 보이는 코드”보다 “이 파일이 누구를 상속하고 어떤 함수를 호출하는가”가 더 중요하다.

일반 RAG는 코드 조각의 의미가 비슷한지를 잘 찾지만, 자식 클래스가 실제로 상속하는 부모나 멀리 있는 interface를 놓칠 수 있다. 코드에서는 이 한 번의 누락이 import·API·상속 오류로 이어진다.

초등학생도 이해하는 설명

레시피 한 줄만 비슷하다고 그 재료의 부모 레시피까지 자동으로 따라오는 것은 아니다. 코드에는 “이 함수는 저 부모 함수에 의존한다”는 관계 지도가 필요하다.

02Architecture · 구조

그래프는 코드의 관계를 보존한다

한눈에 요약

HCRG는 AST에서 결정적으로 뽑은 구조를 property graph에 넣고, 전체 architecture skeleton은 Context Cache에 재사용한다. 명시적 관계와 벡터 유사도를 함께 쓴다.

이 논문에서 Graph RAG의 “graph”는 지식 표현 관계이고, 검색 가속 ANN 그래프와는 다른 층이다.

그래프의 노드는 파일·클래스·메서드이고, 간선은 INHERITS·CALLS·IMPORTS다. migration orchestrator가 DAG(방향성 순환이 없는 그래프)를 만들고 부모를 먼저 변환한 뒤 자식 prompt에 넣는다. 동시에 AST 노드 embedding을 Spanner에 저장해 암시적 관계는 vector fallback으로 찾는다.

검색 계열 1차 판별

분류: knowledge/structure Graph RAG + vector fallback. Microsoft GraphRAG의 community report·DRIFT가 아니라, 코드 AST의 명시적 관계와 topological order가 핵심이다. HNSW/Vamana 내부 그래프도 아니다.

초등학생도 이해하는 설명

코드 파일을 그냥 책장에 꽂는 대신, “A는 B의 자식, C를 호출, D를 import”라는 선으로 연결한다. 번역할 때 부모부터 읽어 자식이 엉뚱한 부모를 상상하지 않게 한다.

03Evaluation · 평가

겉보기 문장 점수는 구조 오류를 숨길 수 있다

한눈에 요약

Graph RAG는 hallucination·dependency·parent-child consistency를 개선했다. 반대로 전역 context가 너무 많아 cyclomatic complexity와 docstring preservation은 낮아졌다.

좋은 번역은 글자가 닮은 번역이 아니라 실제로 import되고 부모-자식 계약을 지키는 번역이다.

초등학생도 이해하는 설명

두 답안이 문장 모양은 비슷해 보여도 한 답안은 실제 실행되고 다른 답안은 없는 함수를 부를 수 있다. 그래서 글자 점수만 보면 안 되고, 직접 실행해 관계를 확인해야 한다.

04Trade-offs · 절충

관계가 복잡할 때만 비싼 구조를 쓴다

한눈에 요약

Graph RAG는 구조적으로 복잡한 파일에서 API hallucination을 크게 줄였지만, 단순 파일에서는 두 방식의 차이가 작았다. 전역 구조를 모두 보여주면 방어적 과잉 설계가 생길 수 있다.

실무적으로는 복잡도·의존성 신호에 따라 일반 RAG와 Graph RAG를 라우팅하는 hybrid가 자연스럽다.

초등학생도 이해하는 설명

간단한 심부름에는 지도 전체가 필요 없지만, 여러 버스와 환승이 있는 여행에는 노선도가 필요하다. 다만 노선도를 너무 많이 펼치면 어디를 봐야 할지 오히려 헷갈릴 수 있다.

05Limits · 한계

Graph RAG를 기본값으로 만들기 전에 볼 것

한눈에 요약

Graph RAG는 구조 계약을 지키는 데 강하지만, 전역 문맥이 많아지면 복잡도와 주석 보존을 희생할 수 있다. 평가도 코드 실행·AST 구조 중심이어야 한다.

이 논문은 Graph RAG의 무조건 우위가 아니라, 구조 의존성이 높은 작업에서의 조건부 우위를 보여준다.

한 개 repository의 Java→Python 변환, Gemini 2.5 Pro, Google Cloud Spanner·Vertex Context Cache 설정에 기반한 사례 연구다. 저자들은 HCRG 원리는 플랫폼 독립적이라고 말하지만, 다른 언어·reflection·동적 의존성·대규모 저장소에서의 재현은 남은 과제다.

Context Cache TTL은 1시간이고, 전역 skeleton을 매번 새로 보내는 비용을 줄인다. 하지만 cache 구축·AST 파싱·graph 갱신 비용과 실제 운영에서 구조가 바뀔 때의 stale fact 문제를 함께 측정해야 한다.

초등학생도 이해하는 설명

큰 지도를 보여주면 길을 잘못 들 가능성은 줄지만, 모든 골목을 한꺼번에 보면 운전자가 과하게 우회할 수 있다. 필요한 관계만 골라 보여주는 다음 단계가 필요하다.

＋One-page Summary · 한 장 정리

이 논문을 한 장으로

01
결론: 구조 의존성이 높은 코드 변환에서는 Graph RAG가 hallucination과 API 누락을 크게 줄였다.
02
단순 파일은 일반 vector RAG로 충분할 수 있다.
03
Graph RAG는 복잡도와 docstring 보존을 악화시킬 수 있어 선택적 hybrid가 합리적이다.
04
정말 쉽게 한 문장: 코드의 가족관계와 호출관계를 지도처럼 보여주면 번역 실수는 줄지만, 지도를 너무 크게 보여주면 다른 실수가 생긴다.
