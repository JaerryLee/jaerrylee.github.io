01Motivation · 문제

사람이 쓴 검색어 시험으로 agent 검색기를 평가하면 어긋난다

한눈에 요약

Q2D-Web은 production 대화에서 agent가 재작성한 질의와 web-scale corpus를 결합한다. 첫 단계 retriever가 놓친 문서는 뒤 reranker와 LLM이 볼 수 없으므로 recall을 현실적으로 재야 한다.

기존 큰 corpus는 시험 질의가 적고, 질의가 많은 benchmark는 corpus가 작다. 또한 click 하나만 정답으로 두면 실제로 관련된 미표시 문서를 오답으로 채점하는 false negative가 커진다.

Q2D-Web은 약 190M 문서, 69,721 agent 질의, query당 평균 99.6개의 양성 judgment를 제공한다. corpus와 질의는 오염 방지를 위해 공개하지 않고 open-weight model용 leaderboard만 운영한다.

초등학생도 이해하는 설명

학교 시험지가 쉬운 연습문제 50개뿐이면 실제 운동장에서 누가 잘하는지 모른다. 이 논문은 AI 검색기가 실제로 받는 말투와 아주 큰 책장을 넣은 시험장을 만든다.

02Prior Benchmarks · 기존 연구

큰 책장·많은 질문·깊은 채점표를 한 번에 갖춘 자료가 드물다

한눈에 요약

TREC·MS MARCO·BEIR·BrowseComp 계열은 각각 장점이 있지만 Q2D-Web이 겨냥한 세 축을 동시에 충족하지 않는다.

MS MARCO Web Search는 약 1억 문서지만 시험 질의 9,374개와 query당 click label 하나다. BrowseComp-Plus는 사람이 검증한 evidence가 있지만 830개 research query와 10만여 문서다.

Q2D-Web은 agent 전체의 최종 답보다 첫 단계 retrieval을 분리해 평가한다. 이는 “정답을 말했나”가 아니라 “나중 단계가 읽을 evidence 후보를 충분히 올렸나”를 묻는다.

초등학생도 이해하는 설명

축구팀 전체 점수 대신 첫 패스를 따로 시험한다. 첫 패스가 공을 못 보내면 다음 선수는 아무리 잘해도 슛할 수 없다.

03Queries & Corpus · 데이터

23천 검색에서 69,721개의 기계 작성 질의를 뽑다

한눈에 요약

질의의 82.3%는 support query다. query별 production top-5,000 결과를 합치고 5-gram MinHash-LSH로 거의 같은 문서를 합쳐 약 190M 문서를 만든다.

12,365개 primary query는 사용자 의도를 다시 쓰고, 57,356개 support query는 대체 표현·배경·인접 entity를 찾는다. 월·분야·언어 비율을 production 분포에 맞추고 PII detector에 걸린 질의는 제외한다.

문서 평균 길이는 13,169자다. corpus는 임의 web sample이 아니라 실제 검색 상위 후보들의 합집합이므로, 각 질의와 그럴듯하게 가까운 hard distractor가 많다.

초등학생도 이해하는 설명

사용자가 한 질문을 하면 AI가 대표 질문 한 개와 도우미 질문 여러 개를 만든다. 그 질문들로 실제 찾아 본 책들을 모아, 헷갈리기 쉬운 거대한 책장을 만든다.

04Judgments & Sampling · 채점

세 개의 불완전한 정답표를 합치고 어려운 오답을 남긴다

한눈에 요약

Citation, 내부 Web Ranking, 이전에 미채점된 후보에 대한 LLM 판정을 각각 보존한다. 모든 양성을 남기고 RRF가 고른 hard distractor로 약 31.7% 축소 corpus를 만든다.

Citation은 실제 답변에 쓰였다는 장점이 있지만 중복 evidence를 덜 표시한다. Web Ranking은 BM25+dense+cross-encoder stack의 편향을 가진다. LLM judge도 길고 유창한 글을 선호할 수 있다. 세 정답표를 따로 보고 합친 이유다.

full corpus에서 pplx-embed-v1-4b 한 번은 4,608 H200 GPU-hour, 300M model도 약 200 H200 GPU-hour가 든다.

장난감 예: 관련 문서 10개는 무조건 남기고, 여러 검색기가 “관련 있어 보인다”고 상위에 올렸지만 정답 표시는 없는 문서 1,000개를 섞는다. 아무 문서나 뽑는 것보다 실제 검색 혼동을 보존한다.

초등학생도 이해하는 설명

정답 책은 모두 남긴다. 오답 책은 검색기들이 자꾸 헷갈리는 책 위주로 골라 작은 시험장을 만든다. 그러면 책장은 줄어도 누가 더 잘 찾는지 순서는 비슷하게 남는다.

06Analysis · 해석

약한 BM25가 다른 누구도 못 찾은 정답을 가장 많이 찾았다

한눈에 요약

BM25의 전체 Recall은 44.77로 최하였지만 독점 양성 14,621개로 2위의 거의 6배였다. 강한 neural model끼리만 합치는 것보다 서로 다른 family를 섞을 가능성을 보여 준다.

pplx-4B와 Nemotron-8B는 전체 recall이 높지만 독점 양성은 각각 884개와 705개다. 평균 점수와 ensemble 기여는 같은 순서가 아니다.

hard negative 표본의 15.8%는 재판정하면 실제 relevant였다. 진짜 hard negative는 wrong aspect 39.0%, partial 17.8%, related entity 13.8%가 컸다. 어떤 retriever도 top-1000에 못 올린 6,424개 hard positive는 lexical gap 51.1%, truncation 17.7%, multilingual 15.4%였다.

07Decision · 결론

검색 설계는 평균 1등 한 개가 아니라 질의 분포와 독점 recall로 고른다

한눈에 요약

agentic RAG에서는 primary/support를 나눠 보고, dense·late·lexical의 독점 양성과 실패 유형을 측정해야 한다. 축소 corpus는 빠른 후보 선별용이지 절대 점수의 대체물이 아니다.

실무 임계점은 문서 수가 커졌다는 사실만이 아니다. agent가 만든 support query에서 recall이 떨어지고, 강한 dense retriever들이 같은 정답을 반복해서 놓치는지가 hybrid retrieval을 켤 신호다.

이 논문은 retrieval benchmark이지 GraphRAG 논문이 아니다. HNSW나 knowledge graph traversal을 비교하지 않는다. BM25·single-vector dense·multi-vector late interaction이라는 검색 표현 계열을 비교한다.

가장 큰 근거 경계는 private benchmark다. 개인정보 보호와 contamination 방지에는 유리하지만, 외부 연구자가 corpus·질의·label을 직접 감사하거나 완전히 재현할 수 없다. LLM judge가 자기 label을 재검토한 error analysis도 독립 판정은 아니다.

초등학생도 이해하는 설명

AI가 실제로 묻는 질문으로 먼저 시험하고, 한 검색기가 계속 놓치는 종류를 다른 검색기가 채우는지 본다. 작은 시험장은 빠른 예선이고, 마지막 결승은 큰 책장에서 다시 해야 한다.
