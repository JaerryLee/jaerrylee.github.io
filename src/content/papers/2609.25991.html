01PROBLEM · 문제 제기

RAG가 문서를 찾아 붙이는 데서, 에이전트가 지식을 읽는 방법을 배우는 데로

한눈에 요약

일반 RAG는 질문마다 관련 문서를 찾아 한 번에 붙여 주지만, 무엇을 먼저 읽고 어디로 더 들어갈지는 시스템이 대신 결정한다.

이 논문은 지식을 에이전트가 직접 탐색할 수 있는 파일 구조로 정리하면, 검색 결과가 아니라 “읽는 방법” 자체를 재사용할 수 있다고 제안한다.

논문은 Knowledge-as-Skill이라는 설계를 제안한다. 지식을 하나의 긴 벡터 데이터베이스로만 보지 않고, 발견용 SKILL.md, 폴더별 이동 경로를 적은 index.md, 실제 문서와 메타데이터로 나누어 둔다.

이 구조의 목표는 LLM이 매번 검색기에서 받은 문단을 수동으로 조립하는 대신, 먼저 지식 영역을 발견하고, 목차를 따라가며, 필요한 문서만 선택하고, 출처와 갱신 시각을 확인하게 만드는 것이다.

초등학생도 이해하는 설명

도서관에서 사서가 책 몇 쪽을 대신 복사해 주는 것이 보통 RAG라면, 이 논문은 “도서관 안내판 → 책장 표지 → 책 속 내용”을 만들어 AI가 스스로 길을 찾게 하자는 생각이다. 단, 파일을 읽는다고 저절로 진실을 보장하는 것은 아니다.

02DESIGN · 구조

세 층으로 나눈 지식: 발견, 이동, 내용

한눈에 요약

SKILL.md는 이 지식 묶음이 무엇인지, 언제 쓸지, 첫 단계가 무엇인지 알려 주는 진입점이다.

index.md는 폴더 안에 어떤 주제와 문서가 있는지 안내하고, 문서 본문은 YAML frontmatter로 출처·날짜·식별자를 함께 가진다.

세 층은 발견 계층, 탐색 계층, 지식 계층이다. 검색 결과 하나를 받는 대신, 에이전트가 필요한 만큼만 아래로 내려가는 계층형 읽기를 유도한다.

TABLE 1Corpus2Skill과 Knowledge-as-Skill의 구조 비교
차원Corpus2SkillKnowledge-as-Skill
구축문서를 스킬로 변환스킬·폴더·문서를 계층으로 생성
탐색스킬 설명에 의존SKILL.md → index.md → 문서
보조 장치검색·요약 중심frontmatter·로그·캐시

원문 Table 1을 한국어로 재구성했다.

SKILL.md에는 설명과 사용 시점이, index.md에는 하위 폴더와 대표 질문이, 문서의 YAML에는 제목·출처·업데이트 정보가 들어간다. 구조를 고정하면 에이전트가 “어떤 파일을 언제 열지”를 추론할 여지가 생긴다.

초등학생도 이해하는 설명

학교 책장에 “과학 → 생물 → 식물” 표지가 붙어 있는 모습과 비슷하다. SKILL.md는 학교 안내문, index.md는 책장 표지, 문서 본문은 실제 교과서다. 이 논문은 표지를 정성껏 만드는 것이 핵심이라고 말한다.

03PIPELINE · 구축과 사용

문서를 넣는 순간부터 질문을 푸는 순간까지

한눈에 요약

PDF·Word·웹·메모를 정규화하고, 폴더·문서 메타데이터·로그를 생성한다.

질의 시에는 스킬을 발견하고, 목차를 확인하고, 필요한 원문을 읽은 뒤 출처를 포함해 답한다.

구축 단계는 단순 임베딩 생성이 아니다. 저자는 파일 형식을 통일하고, 문서를 주제별 디렉터리에 배치하고, 각 문서에 provenance를 붙인다. 질의 단계는 discover → navigate → read → answer 흐름을 따른다.

초등학생도 이해하는 설명

큰 창고에서 물건을 찾는다고 하자. 물건을 하나씩 전부 꺼내 보는 대신 “문구류 창고 → 연필 선반 → HB 연필 상자”로 이동한다. 이 논문은 AI에게 이런 안내판을 만들어 주는 방법이다.

04EVALUATION · 예비 평가

정확성은 좋아졌지만, 읽는 횟수와 답변 방식에는 대가가 있다

한눈에 요약

WixQA라는 작은 평가에서 Factuality와 Context Recall은 Corpus2Skill보다 높았지만 Token F1·Faithfulness·Context Precision은 낮거나 혼합된 결과였다.

저자들은 이를 최종 승리로 주장하지 않고, 구조화된 지식 탐색의 가능성을 보여 주는 예비 신호로 해석한다.

Table 3의 수치는 “무엇을 잘 맞혔나”를 서로 다른 관점에서 잰다. Factuality 0.889는 답변에 사실이 포함된 정도이고, Context Recall 0.816은 필요한 근거를 얼마나 찾아왔는지다. 같은 답이라도 토큰 겹침과 근거 충실성은 다르게 움직일 수 있다.

TABLE 3예비 WixQA 결과
지표OursCorpus2Skill
Token F10.4120.456
Factuality0.8890.767
Faithfulness · grounded0.8100.859
Context Recall0.8160.708
Context Precision0.7610.829
Hallucination Rate4.5%4.5%
평균 Turns4.0152.38
높은 값이 항상 같은 의미는 아니다. Hallucination Rate는 낮을수록 좋고, Turns는 적을수록 질의 상호작용이 짧다. 원문은 예비·교차 연구 비교임을 명시한다.

따라서 “정확도가 88.9%”라고 읽으면 안 된다. Factuality 0.889는 해당 평가 정의와 데이터셋 안에서의 점수이며, 전체 사실의 88.9%가 보장된다는 뜻이 아니다. 오히려 여러 지표를 함께 보면 구조가 근거 회수에는 도움을 주지만, 더 많은 읽기 단계와 다른 답변 스타일을 요구했음을 알 수 있다.

초등학생도 이해하는 설명

시험 점수표에 국어·수학·발표 점수가 따로 있는 것과 같다. 한 과목 점수가 올랐다고 모든 과목이 좋아진 것은 아니다. 이 표에서는 “필요한 근거를 찾는 힘”은 좋아졌지만, 답을 짧게 겹쳐 맞히는 점수는 낮아질 수 있음을 보여 준다.

05DISCUSSION · 한계와 적용

LLM-Wiki의 핵심은 저장 방식보다 읽는 규칙이다

한눈에 요약

구조화된 지식은 agent-native retrieval의 출발점이지만, 현재 실험은 작은 데이터·예비 비교이고 비용·지연·유지보수는 충분히 측정되지 않았다.

실무에서는 provenance, 갱신 시각, 탐색 로그를 보존하고, 구조 탐색과 벡터·키워드 검색을 함께 평가해야 한다.

Knowledge-as-Skill은 LLM-Wiki를 “문서 모음”이 아니라 “에이전트가 읽을 수 있는 운영체계”로 보게 한다. 그러나 계층을 만드는 비용, 잘못된 index가 유도하는 편향, 신선한 문서를 다시 구조화하는 비용은 아직 열려 있다.

이 작업의 종합 판단

LLM-Wiki를 만든다면 SKILL.md·index.md·문서 메타데이터·로그를 최소 구성으로 채택할 만하다. 다만 기존 RAG를 버리기보다, 구조 탐색으로 범위를 줄인 뒤 dense/sparse 검색과 재랭킹을 호출하는 혼합 경로가 현실적이다. 이는 논문의 직접 실험이 아니라 이 큐레이션의 설계 해석이다.

초등학생도 이해하는 설명

정리하면 AI에게 책을 많이 주는 것보다, 책장을 잘 정리하고 “어디부터 읽을지” 알려 주는 것이 중요하다는 이야기다. 하지만 정리하는 사람의 실수가 있으면 AI도 엉뚱한 책장을 먼저 볼 수 있다.

AWORKER ANALYSIS · 별도 분석 부록

검색 계열 1차 판별 · LLM-Wiki/agent-native knowledge base

이 절은 논문 원문이 아니라, 이 큐레이션 작업에서 추가한 검색 계열 분류다. 저자의 본문 장 번호와 구분한다.

분류

LLM-Wiki·agent-native knowledge-base organization에 해당한다. Microsoft GraphRAG의 community report/global-local/DRIFT, HippoRAG의 PPR·passage node·associative memory, HNSW/Vamana ANN 그래프가 핵심 구성으로 보이지 않는다. 노드-간선 지식 그래프가 아니라 디렉터리와 문서 구조를 에이전트가 읽는 방식이다.

따라서 이 논문에서 “graph”라는 단어가 나오더라도 의미 그래프 RAG로 오해하면 안 된다. 실제 비교 대상은 문서 구조와 에이전트 탐색 절차다.
