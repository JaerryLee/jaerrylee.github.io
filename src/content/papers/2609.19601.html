01MOTIVATION · 왜 근거를 열어야 하나

답보다 먼저 만들어지는 “근거 바구니”를 살펴보자

한눈에 요약

일반 RAG는 문서를 찾아 답을 쓰지만, 사용자는 어떤 검색 방향을 시험했고 어떤 문장을 버렸는지 보기 어려운 경우가 많습니다.

문헌 종합에서는 답 문장뿐 아니라 그 답에 넣은 근거의 범위와 출처도 중요합니다.

FootprintRAG가 바꾸려는 것은 “LLM이 답을 쓰는 방식”보다 답을 쓰기 직전의 증거 선택 과정입니다.

논문은 문헌 탐색을 한 문장 질문에 top-k 자료 몇 개를 붙이는 일로 보지 않습니다. 예를 들어 연구 동향이나 연구 공백을 찾을 때는 질문을 여러 방향으로 풀어 검색하고, 겉으로는 비슷해도 쓸모가 약한 자료를 걷어내며, 자동 순위에서 밀린 중요한 결과를 다시 확인해야 합니다. 이 과정이 가려져 있으면 사용자는 빠진 근거나 근거의 편향을 알아차리기 어렵습니다.

저자들은 그래서 생성 결과만 사후 검토하지 않고, 생성에 넣을 evidence context(근거 맥락) 자체를 분석 대상이자 사용자가 수정할 수 있는 대상으로 만듭니다. 이것은 새로운 vector DB나 지식 그래프를 제안하는 논문이라기보다, RAG의 중간 결과를 보이게 하는 시각 분석 시스템입니다.

초등학생도 이해하는 말

책을 요약해 달라고 시키기 전에, 어떤 책과 문장을 골라 읽었는지 펼쳐 보여 주는 도구입니다.

02USER NEEDS · 연구자는 무엇을 원하나

좋은 검색 결과와 좋은 근거는 같은 말이 아니다

한눈에 요약

저자들은 연구자 8명과 약 45분씩 인터뷰하고, 반복되는 불편을 네 가지로 정리했습니다.

여러 검색어를 비교하고, 약한 근거는 빼며, 빠진 근거는 찾아 넣고, 최종 근거를 확인한 뒤에 종합하고 싶다는 요구입니다.

“검색어와 비슷한 문서”가 꼭 “내 결론을 뒷받침할 문서”는 아닙니다.

인터뷰 결과, 연구자는 여러 검색 방향을 나란히 시험하고 싶어 합니다. 자동 검색이 확장한 질문을 알 수 없으면 충분한 범위를 봤는지 판단할 수 없기 때문입니다. 검색된 후보 안에도 배경 설명, 중복, 약한 관련성, 특정 결과나 방법을 직접 보여 주는 근거가 섞입니다. 그래서 자동 순위는 최종 판결이 아니라 사람이 검토할 첫 번째 제안이어야 한다고 봅니다.

또한 top-k 밖에 있는 유용한 자료는 자동 절단으로 가려질 수 있습니다. 저자들은 무한히 많은 탈락 문서를 보여주기보다, 현재 근거와 연결되면서도 덜 중복되거나 출처가 부족한 부분을 보완할 후보만 선별해 사용자에게 제시합니다. 인용을 붙였다는 사실만으로 무엇을 근거로 썼는지 충분히 설명되지 않으므로, 생성 전에 근거 집합을 확인하는 것을 목표로 합니다.

형성 연구에서 설계 요구로 FORMATIVE STUDY → DESIGN GOALS

초기 인터뷰에는 문헌 검색·종합 경험이 있는 8명이 참여했습니다. 연구진은 결과를 병렬 질의 비교, 근거 수정, 놓친 후보 노출, 생성 전 근거 확인·출처 추적이라는 네 설계 목표로 바꿨습니다. 이 인터뷰는 사용자 요구를 찾는 탐색 단계이지, 시스템의 성능을 통계적으로 증명하는 실험은 아닙니다.

초등학생도 이해하는 말

검색어와 닮은 문서라도 내 답을 도와주지 않을 수 있으니, 사람이 살펴보고 고치게 해 달라는 뜻입니다.

03METHOD · 어떻게 근거를 다루나

논문을 잘라 근거 카드로 만들고, 검색의 발자국을 남긴다

한눈에 요약

논문은 텍스트와 그림을 근거 단위로 바꾸고, 각 단위에 원문 위치와 임베딩을 붙입니다.

검색을 여러 차례 비교한 뒤, 시스템은 근거 후보를 제안하고 사용자가 선택한 상태만 최종 생성에 넣습니다.

핵심 설계는 retrieval을 숨겨진 함수 호출이 아니라 추적 가능한 상태 변화로 바꾸는 것입니다.

텍스트는 문서 구조와 문단 경계를 따라 의미 단위로 나누고, 출처 논문·절·페이지 같은 provenance(출처 정보)를 보존합니다. 그림은 원본 이미지에 캡션, 주변 문장, LLM이 만든 설명을 붙여 텍스트 기반 근거 단위로 만듭니다. 저자들은 이 통일 방식이 편리하지만 세밀한 시각 정보나 차트의 숫자·공간 관계를 놓칠 수 있다고 한계에 적습니다.

초기 질문은 병렬 질의 변형으로 넓어지고, 여러 라운드 검색 결과는 matrix view에서 비교됩니다. 각 후보에는 질문 변형을 얼마나 뒷받침하는지 High·Medium·Low 평가가 붙습니다. 사용자는 현재 검색에서 재순위화 뒤 빠진 local candidate를 추가로 살펴보거나, 현재 후보에 없지만 corpus 전체에서 관련 있다고 평가된 ERS-ranked 후보를 확인할 수 있습니다. ERS는 관련성·보완성·질의 적합도를 결합해 추가 후보의 순서를 매깁니다. 자동 평가가 근거를 승인하는 것이 아니라 검토할 위치를 좁히는 보조 신호입니다.

마지막에는 사용자가 근거를 포함·제외하고 상태를 확인한 다음 그 상태를 바탕으로 요약을 생성합니다. 그러므로 RAG는 여전히 임베딩 검색을 쓰지만, 이 논문의 기여는 임베딩 자체보다 검색 결과를 사람이 고칠 수 있는 근거 작업 공간으로 만드는 데 있습니다.

초등학생도 이해하는 말

책갈피마다 책 제목과 페이지를 붙인 뒤, 여러 검색 목록을 비교해서 쓸 부분을 직접 골라 담습니다.

04EVALUATION · 무엇을 확인했나

작은 문헌 탐색에서 사용자가 실제로 근거를 손봤다

한눈에 요약

논문은 두 사례 연구, 10명 사용자 연구, 기존 시스템과의 작업 흐름 비교를 제시합니다.

10명 연구에서 참가자들은 생성문을 계속 다시 쓰기보다 검색 방향과 근거 묶음을 주로 고쳤습니다.

이 논문이 보여주는 것은 일반 QA 정확도에서의 우승이 아니라, 문헌 탐색 중간 과정의 가시성과 개입 가능성입니다.

사례 1은 48편의 논문을 대상으로 한 문헌 탐색이며, 사례 2는 16편 규모의 LLM 시각화 관련 코퍼스입니다. 사용자 연구에는 문헌 검색·논문 읽기 경험이 있는 10명(대학원생과 초기 경력 연구자)이 참여했습니다. 참가자들은 FootprintRAG를 처음 사용했으며 16편 문헌 코퍼스에서 탐색 과제를 수행했습니다.

5점 척도 질문에서 검색어 확장 가시성은 평균 4.6, 후보의 유용성 판단은 4.8, 후보 근거 수정은 4.9, 전역 보완 후보의 유용성은 4.4, 생성 전에 근거 맥락을 확인하는 것은 4.9였습니다. 상호작용 기록에서는 참가자당 평균 근거 작업 25.1회, 재순위화된 단위 제거 10.6회, ERS 후보 추가 12.9회, 요약 수정 3.7회가 보고됩니다. 이 숫자는 10명과 제한된 과제 안에서 관찰한 조작·평가이지, 답변 정확도가 4.9/5로 상승했다는 뜻이 아닙니다.

05LIMITS · 어디까지 믿어야 하나

근거를 고칠 수 있다고 근거가 자동으로 참이 되는 것은 아니다

한눈에 요약

평가는 10~48편 규모의 제한된 코퍼스와 10명 사용자에 기반해 일반적인 효과 크기를 확정하지 못합니다.

추가 검색·LLM 평가·요약 호출은 비용과 지연을 늘리고, 그림 설명은 중요한 시각 세부 정보를 놓칠 수 있습니다.

FootprintRAG는 답의 진실성을 자동 보증하는 fact checker나 persistent knowledge wiki가 아닙니다.

첫째, 저자들도 현재 사례가 10~48편의 과제별 코퍼스이므로 더 큰 코퍼스와 다른 분야로 일반화된다고 주장할 수 없다고 적습니다. 둘째, query expansion, 다중 라운드 검색, 후보 평가, 요약 때문에 한 번 검색하는 RAG보다 지연이 커집니다. 저자들은 캐시, batching, 경량 평가, 적응형 종료를 완화책으로 제안하지만 손익분기점은 별도 측정해야 합니다. 셋째, 그림은 이미지 직접 임베딩 대신 캡션·주변 텍스트·LLM 설명으로 표현하므로, 수치 추세와 공간 배치를 놓칠 수 있습니다. 넷째, LLM prompt와 모델 선택에 민감할 가능성이 있습니다.

우리 연구에 주는 경계

이 논문은 RAG 근거를 보여주고 수정하는 UI가 유용할 수 있음을 시사합니다. 그렇다고 사용자가 승인한 근거가 사실 검증을 통과했거나, 오래 보존할 위키 지식으로 이미 승격됐다는 뜻은 아닙니다. 근거 승인, 주장 검증, Wiki 반영은 각각 별도 상태로 남겨야 합니다.

＋Glossary · 핵심 용어

핵심 용어 정리

근거 단위Evidence unit

검색·평가·수정할 수 있게 문단이나 그림을 나눈 조각입니다.

근거 맥락Evidence context

답을 만들 때 모델에 실제로 넣을, 선택된 근거들의 묶음입니다.

출처 정보Provenance

근거가 어느 논문·페이지·절에서 왔는지 다시 찾아갈 수 있는 흔적입니다.

재순위화Reranking

처음 찾은 후보들의 순서를 더 정밀한 기준으로 다시 매기는 일입니다.

ERSEvidence Relation Score

현재 근거에 덧붙일 전역 후보를 관련성·보완성 등으로 정렬하는 점수입니다.

＋One-page Summary · 한 장 정리

이 논문을 한 장으로

01
RAG의 답만 보여주지 말고, 답을 만들기 전에 고른 근거 묶음도 확인 가능하게 한다.
02
병렬 질의, 제외된 후보, 보완 후보를 나눠 보여줘 검색 범위와 빠진 근거를 살펴본다.
03
사람의 수정은 답변 생성 전에 이뤄지며, 선택된 근거의 원문 출처를 계속 보존한다.
04
사용자 연구에서 근거 수정과 생성 전 확인은 평균 4.9/5였지만 표본은 10명이다.
05
대규모 효과·사실성 검증·전체 시스템 비용은 이 연구만으로 결론내릴 수 없다.
