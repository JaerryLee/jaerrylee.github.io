01Design · 설계 · 수동+능동의 조합

살아 있지만 느린 연결을 보려면 직접 물어봐야 한다

한눈에 요약

passive eBPF는 실제 data plane을 보지만 idle path를 확인하지 못한다. active TCP probe는 반대로 아무 트래픽이 없어도 연결성을 확인한다.

NetMon은 sidecar agent와 central server로 anomaly를 모으고 topology-aware correlation을 수행한다.

5초마다 peer를 probe하고, XDP/TC eBPF가 RTT·retransmission·RST를 읽으며, 중앙에서 pod·worker 상태를 계산한다.

보완 관계

active는 경로 존재를 확인하고 passive는 실제 경로 품질을 확인한다. 어느 한쪽만으로는 gray failure를 놓칠 수 있다.

초등학생도 이해하는 설명

전화가 오지 않는다고 전화선이 끊겼다고 알 수 없다. 가끔 직접 전화를 걸어보고, 통화 중 잡음도 들어야 한다.

02Detection · 탐지 · agent와 correlation

로컬 민감도와 중앙 국소화를 나눈다

한눈에 요약

agent는 EMA·z-score·threshold로 anomaly를 만들고, server는 30초 window의 패턴을 worker/pod 상태로 합친다.

CUSUM은 drift를, probe failure와 topology map은 단절 위치를 포착한다.

민감한 local detector가 noise를 많이 내도, central correlation이 여러 출처의 증거를 겹쳐 high-confidence fault를 만든다.

03Evaluation · 실험 · fault injection

실제 Kubernetes에서 여섯 부류의 장애를 주입했다

한눈에 요약

10/20/50% simulated UE load에서 latency, jitter, packet loss, bandwidth, partition, termination, gradual degradation을 반복했다.

resource overhead와 detection/correlation latency를 함께 측정했다.

04Results · 결과 · 탐지·국소화·오버헤드

10ms 지연과 5% 손실도 수 초 안에 보였다

한눈에 요약

latency fault는 2–10초 안에 탐지, 6–20초에 worker 국소화됐다. full partition은 9–11초에 탐지·correlation됐다.

pod당 3.4 millicores CPU와 4.5 MiB memory, 10-pod 전체 약 35 millicores·47.6 MiB였다.

5% packet loss는 3–17초 탐지지만 50% loss에서는 monitoring traffic도 굶어 correlation이 133초까지 늘거나 실패했다.

운영 해석

빠른 경보의 비용은 baseline anomaly volume이다. 18시간 정상 운전에서도 2,902 anomalies/hour가 생겨 soft correlation에는 사람의 판단이 필요했다.

초등학생도 이해하는 설명

감지기를 아주 민감하게 만들면 작은 연기도 잡지만 평소에도 알람이 자주 울린다. 여러 감지기를 함께 봐야 진짜 불을 고른다.

05Limits · 한계 · 확장성과 보안

모니터링 자체가 장애 경로에 놓인다

한눈에 요약

full-mesh probe는 O(N²)로 커지고, central correlator는 single point of failure다.

eBPF에는 CAP_BPF·CAP_NET_ADMIN이 필요하며 threshold는 새 환경에서 재조정해야 한다.

다음 단계는 worker 단위 계층 aggregation, central server leader election, adaptive threshold, severe bandwidth에서도 살아남는 out-of-band 경로다.

도입 전 확인

cluster 규모에서 probe 비용을 감당하는가? monitoring traffic이 업무 traffic과 같은 병목을 타는가? eBPF 권한을 보안 정책이 허용하는가?

초등학생도 이해하는 설명

경보 시스템이 유일한 전화선에 매달려 있으면 전화선이 끊길 때 경보도 못 보낸다. 관측 경로 자체를 설계해야 한다.

＋Glossary · 핵심 용어

핵심 용어 정리

eBPF/XDP커널 데이터 경로 관측

user space보다 이른 네트워크 경로에서 패킷·RTT를 수집하는 방법.

active probing능동 probe

실제 트래픽이 없어도 peer 연결을 주기적으로 시험하는 방식.

CUSUM누적합 변화 탐지

평균·분산의 작은 이동을 누적해 distribution shift를 찾는 방법.

gray failure부분 장애

프로세스는 살아 있지만 latency·loss 등 품질이 나빠진 상태.

correlation상관 분석

여러 pod·worker의 anomaly를 합쳐 fault 위치를 추정하는 단계.
